# DSH Bay 18.x 使用教程

更新日期：2026-11-11。适用版本：`dsh-bay@0.2.2-alpha.18.1`，宿主 DSH `0.2.2-rc.1`。步骤根据当前组件与服务核对；用户安装环境的完整验收仍需实际执行，见[验证记录](VALIDATION.md)。

本教程围绕“插件实验室”示例，从新建项目走到导出和接收后继续工作。示例名称可替换为你的真实项目。

常用入口：[新建工作台](#3-创建第一个工作台) · [关联项目](#4-为区域关联项目) · [对话](#6-新建选择与整理对话) · [Bay Agent](#7-使用-bay-agent-组织任务) · [重新打开项目](#8-关闭区域重新打开项目与切换目录) · [导出](#12-导出完整工作台包) · [导入](#13-导入后继续工作) · [常见问题](#15-常见问题)。

## 1. 安装与进入

1. 确认 DSH 版本为 `0.2.2-rc.1`，准备对应的私有实验包 `dsh-bay-0.2.2-alpha.18.1.tgz`。
2. 在 DSH 原生插件管理器中安装本地包，按宿主提示启用或重启。
3. 若同一 Profile 还有旧包 `@dsh-workbench/core`，先停用旧包，避免两个工作台插件同时注册。
4. 打开 DSH Bay 的工作台入口，进入总览。开始对话前，确认自己的 DSH 模型连接可用。

插件 `.tgz` 和完整工作台迁移 `.tgz` 虽然可能具有相同扩展名，作用不同：前者在 DSH 插件管理器安装；后者在工作台的“导入工作台包”中恢复，不能互换。

当前没有公开稳定版安装承诺。开发者可以按[封包说明](PUBLISHING.zh-CN.md)本地生成插件包；普通使用者使用对应交付制品。

## 2. 先认识界面

| 位置 | 用来做什么 |
| --- | --- |
| 工作台总览 | 左侧选择工作台，右侧查看详情；选择卡片不会立即进入工作台 |
| 工作台顶栏 | 切换总览与工作台，访问工作台菜单、设置与相关操作 |
| 区域 | 展示一个项目，放置多个对话和工具内页 |
| 项目概览 | 查看或编辑项目背景、记忆，打开历史会话，查看任务 |
| 添加内页菜单 | 在“官方内置”和扩展分类中选择对话、工具或扩展 |
| 浮动工作区 | 使用辅助内页和 Bay Agent；可与区域布局配合 |
| 分享与迁移 | 导出、导入及查询完整包作业和报告 |

工作台是整体空间，项目是长期资料归属，区域只是展示位置。**关闭区域不会删除项目文件、背景、记忆或会话历史。**

常用工作台可以在总览卡片点击 📌 固定到 DSH 原版侧栏，之后从侧栏快捷打开。取消固定只移除快捷入口，不删除工作台。

## 3. 创建第一个工作台

1. 在总览底部点击“创建工作台”，也可以使用顶栏的创建入口。
2. 名称填写“插件实验室”。
3. 点击“选择文件夹”，选择用于存放工作台的父目录。
4. 核对“将在这里创建”的最终路径。需要不同磁盘目录名时，展开“自定义文件夹名称”。显示名称与文件夹名称可以不同。
5. 展开“区域布局”，先选单区域或合适的分区；以后可以调整。
6. “工作背景”可暂时留空，或填写用途。点击 AI 辅助按钮才会请求生成草稿，生成后先审阅。
7. 点击“创建并打开”，等待目录检查、创建和打开阶段完成。

例如父目录是 `D:\Workbenches`，工作台文件夹为“插件实验室”，最终根目录就是 `D:\Workbenches\插件实验室`。这只是 Windows 示例；实际路径以你所用平台的预览为准。

创建工作台会准备持久 Main 会话，但不会因此自动调用模型。首次进入后的区域仍可能需要关联项目目录。

### 创建遇到错误

- **同名或路径无效**：保留表单内容，修改名称/位置后再试。
- **显示“继续创建”**：使用该按钮恢复同一次操作，不要反复新建同名工作台。结果不明确时表单会暂时锁定，避免改参数后造成重复创建。
- **AI 草稿不可用**：可以手动填写或保持背景为空，不必先完成背景才能建工作台。
- **目录保留但会话服务未就绪**：按提示恢复服务后继续，不要手动删除管理文件来绕过恢复。

## 4. 为区域关联项目

在未设置目录的区域进入项目文件夹设置，窗口标题为“区域项目文件夹”。

### 新建文件夹

1. 选择“新建文件夹”。
2. 名称填写 `notes-panel`，只填名称，不需要完整路径。
3. 核对创建位置在当前工作台根目录下。
4. 点击“创建并使用”。

### 使用已有文件夹

1. 选择“选择已有文件夹”。
2. 浏览工作台内的子目录，选择目标目录；需要时进入下一层。
3. 核对已选路径，点击“使用此文件夹”。

目录必须在当前工作台根内。`.bay` 是保留管理目录，不是普通项目。根外项目不会自动移动进来；需要使用时先明确安排其文件到工作台根内，再关联，保留原资料备份。

关联后会出现项目概览。选择目录本身不会创建普通聊天；从概览或添加内页入口开始对话。

多个区域选同一真实目录时会展示同一个项目，共享背景与记忆。当前目录弹窗可能仍显示“各自保留背景”的旧提示，应以项目共享规则为准；该文案已列入稳定化待办。

## 5. 填写背景与管理记忆

### 工作台背景

在总览选中工作台，进入“背景与记忆”，使用“编辑背景”。也可从工作台顶栏的背景入口进入。

示例：

```text
这个工作台用于开发和验证 DSH Bay 容器内页扩展。
优先采用当前 DSH/Core 的公共契约和原生主题。
每次交付需要说明修改内容、验证结果和未验证项。
未明确要求时，不安装到我的日常使用 Profile。
```

### 项目背景

在项目概览的“项目背景”卡片点击“编辑”，填写这个项目的目标、约束、输入和成功标准。

```text
目标：开发一个项目笔记内页，用于记录简短的项目说明。
范围：先完成本地编辑和恢复，兼容 DSH Bay 18.0。
约束：按 owner 提供的项目身份读取上下文，使用 DSH Bay 主题。
验收：多个项目的数据不混用，关闭再打开保留内容，声明可迁移状态。
```

AI 辅助生成的是草稿，先检查再“保存背景”。工作台背景面向整体，项目背景面向具体项目；共享项目的多个区域会读取同一份项目背景。生成内容可能受到读取范围和长度限制，不要把草稿当成已核实的完整项目总结。

### 项目记忆

在项目概览的“项目记忆”点击“管理”：

1. 使用“新增记忆”填写标题、简短摘要与正文。
2. 将确认过的事实、决策和成果位置保存为记忆。
3. 点击已有条目查看来源；使用“上一修订”“当前修订”核对修改历史。
4. 错误或失效内容可以更新或移除，不需要删除整个项目。

示例记忆：“已决定使用 root 内页；当前版本不依赖具体 Session；此决定由用户在设计评审中确认。”未核验推断不应写成确定事实。

背景与记忆由界面/Host 管理。项目目录内的背景 Markdown 是可读投影，直接编辑不等同于同步回应用。原生聊天历史仍由 DSH 保存，项目记忆不替代它。

## 6. 新建、选择与整理对话

### 新建对话

1. 从项目概览点击“新建对话”，或打开区域的添加内页菜单。
2. 在“官方内置”中选择“新建对话”。概览按钮可能先展开同一个内页菜单。
3. 选择当前 DSH 注册的 Agent 模式，确认新建。
4. 会话默认使用所在项目目录，随后可在自己的标签中输入和发送。

开发内页扩展时可选择 DSH 的“创造模式”（当前注册 ID 为 `cordis`）；其他任务根据当前模式介绍选择。新建界面和手动任务表单不会替你保证选到最佳模式，提交前核对选择。

### 打开已有对话

项目概览的“已有对话”列出持久会话，点击“打开”。也可以在添加菜单选择“对话”后选择具体会话；已有会话需匹配目标项目。

同一区域可以有多个独立对话。工具内页若依赖 Session，也要使用明确来源；不能因为目录相同就认为所有标签共享一个会话。

### 关闭和浮动

关闭内页只关闭视图，历史会话仍能从项目概览打开。内页移动到浮动工作区或放入区域时，保留它的项目/会话身份；不匹配的目标按提示处理，不通过强行换绑迁移旧历史。

Bay Agent 标签默认隐藏。点击浮动工作区顶栏的 Bay Agent 按钮显示，再点一次收回该标签；这不会删除 Main 或结束任务。

## 7. 使用 Bay Agent 组织任务

### 在 Main 中描述任务

先让目标项目在一个区域展示，并确认目录正确，再唤出 Bay Agent。

示例指令：

```text
请在 notes-panel 项目开展一个新任务：实现一个简单的项目笔记内页。
先读取项目背景，并查询当前可用 Worker 模式及介绍，选择适合的模式。
任务范围是最小可用版本；完成后提供文件位置、验证结果和未完成项。
不要同时派发两个会修改同一批文件的任务。
```

没有指定 Worker 时，Main 的派发工具先返回可用模式及介绍，这一步不创建任务；Main 选择后再派发。若明确指定“创造模式”，应使用当前注册的 `cordis` 模式。

### 手动创建任务

在“工作台任务”中填写新任务、区域、项目和 Agent 模式，再点击“创建并派发”。这是用户显式选择模式的入口；表单可能默认 Standard，应在提交前核对，不能把它当成 Main 的自动模式选择流程。

### 查看进度与处理暂停

| 状态/入口 | 推荐操作 |
| --- | --- |
| 排队中 / 执行中 | 查看进度或打开 Worker 对话，避免重复创建同一任务 |
| 待处理事项 | 阅读问题；原生授权到 Worker 对话处理，普通答复使用“答复并恢复” |
| 待验收 | 检查报告、文件与测试，符合要求后“验收完成” |
| 已停止 / 失败 / 受阻 | 从项目任务“继续任务”或任务恢复入口续做，检查失败原因 |
| “新建执行尝试” | 属于现有任务的另一次执行，不是另建同名任务 |

要继续旧任务，优先点击任务记录中的对应入口，或在 Main 中明确指向该任务记录。只说“再做一次同样的事”可能被理解为新任务。

停止任务会请求结束当前执行，但不会撤销已完成的文件修改。Main 收到 ready 报告不等于工作已验收。Main 的原生历史压缩、任务 checkpoint 和记忆摘要是不同机制，长时间运行仍需观察实际资源与结果。

## 8. 关闭区域、重新打开项目与切换目录

### 关闭后继续原项目

1. 保存当前内页中的未保存内容，处理真正运行或启动中的关联任务。
2. 使用区域关闭操作，该区域从当前布局移除。
3. 回到总览，选中工作台，在“项目与区域”找到原项目。
4. 点击“在新区域打开”。新区域先显示项目概览。
5. 从“已有对话”打开原会话，或从“项目任务”继续对应任务。

新区域拥有新身份，项目资料保持原归属。也可以新建空区域，选择以前的项目目录。

### 切换关联目录

先关闭或处理当前区域的内页与草稿、停止阻塞的运行任务，再进入区域项目文件夹设置。切换后显示目标项目；旧会话和任务仍属于旧项目，不会跟着区域改工作目录。

等待输入、停止、完成或失败的历史记录本身不应阻止关闭。若仍被阻止，记录提示与对应任务状态，从任务视图确认实际执行是否已结束；不要删除历史来“解锁”。

多个区域共用一个项目时，关闭其中一个不删除其他区域或项目数据。但并行任务可能修改相同文件，目录共享不等于执行隔离。

## 9. 内页扩展与创造模式修复

### 添加与分类

1. 在 DSH 原生插件管理器安装/启用兼容扩展，按提示重启。
2. 在“工作台设置 → 内页与扩展”检查诊断并允许该扩展在工作台使用。
3. 从添加内页菜单选择扩展。官方内页固定在“官方内置”，扩展使用默认或自定义分类。
4. 在“菜单分类文件夹”中创建分类，并为扩展内页选择分类。分类支持收起/展开，搜索会展开匹配结果。

安装成功、工作台允许、实际内页可用是三个不同状态；只完成其中一个并不代表其余全部完成。

### 修复不兼容扩展

1. 在不兼容扩展卡片选择“在创造模式中修复”。
2. 等待在工作台根内 `repairs/` 准备修复项目，并在浮动工作区打开原生创造模式会话。
3. 检查预填草稿中的插件身份、版本和错误。草稿不会自动发送，确认后主动发送。
4. 重复点击优先复用修复会话；已有草稿不会被初始说明覆盖。

修复项目不自动包含插件源码。若创造模式无法定位可编辑源码，应先补足来源，不把自动创建会话当作插件已经修好。开发者从 `/create-workbench-extension` 入口使用[扩展开发技能](../packages/workbench-core/presets/workbench-creator/skills/workbench-extension-development/SKILL.md)。

## 10. 在浏览器继续工作

1. 打开目标工作台的“在浏览器中打开”入口。
2. 等待 Host 准备、浏览器加载和主控确认；不要只因看到画布就认为接管完成。
3. 浏览器接管后操作同一主机目录与会话，桌面管理页保留收回入口。
4. 结束时主动交还，或在桌面点击收回；观察状态恢复、目录/会话刷新和输入就绪进度。

直接关闭浏览器标签通常进入 10 秒重连宽限期；正常收到通知时约 10—12 秒开始桌面恢复。刷新可继续原租约。进程强杀或断网可能无法通知，使用桌面恢复入口；心跳失联判定更长，不能把“立即没有返回”当成数据已丢失。

浏览器主控继承当前工作台的扩展许可。重复标签不能成为第二个主控。工作台包导入若需要目标父目录，由主机 DSH 客户端选择，浏览器文件选择器只负责选择待上传的包。

## 11. 局域网分享

在工作台的局域网分享入口选择“审阅”或“协作”，按需要指定区域、文件范围及额外能力，点击“开始分享”，将界面给出的访问方式交给同一网络的接收方。主机 DSH 需保持运行，访客使用主机上的模型与服务。

- 审阅用于查看；协作可在已有普通/Worker 会话发消息。
- Main 默认不可发送，确需开放时由主控单独选择。
- 超出已授权范围的操作交给主控处理；不会因为能发消息就自动得到任意文件/结构操作能力。
- 分享期间可收紧权限或停止分享；扩大长期范围按界面要求重新建立分享。
- 浏览器交还桌面不自动结束分享，停止分享也不等于终止主控自己的任务。

本节描述当前入口与规则。另一台设备、多浏览器和外部 Runtime 的完整行为仍应按[验证记录](VALIDATION.md)实测。

## 12. 导出完整工作台包

1. 进入“分享与迁移”，选择“导出工作台”，确认来源工作台和“完整工作台包”类型。
2. 核对预览与包含内容，保存待保存的编辑，选择 Windows、macOS 或 Linux 目标系统。接收端仍按实际系统检查，包不会锁定到单一系统。
3. 点击“生成完整包”，观察作业阶段。快照期间与导出冲突的写入或执行可能需等待。
4. 完成后点击“下载完整包”，保留归档及恢复/完整性报告。

完整包目标包含根内工作文件、项目资料、原生会话和附件、任务关联以及可迁移扩展依赖。默认根内文件范围较广，可能包含隐藏文件、Git 数据和依赖目录；分享前按实际内容和报告核对，不能默认只导出源代码。

模型账号、主控/分享凭据和运行进程不随包迁移。目录中的外部链接、缺失附件或不支持的资源需要按报告处理。外部程序仍在写文件时可能无法形成稳定快照，应处理提示后重试。

“布局与扩展”分发用于分享界面/扩展配置，不能代替恢复全部会话与任务的完整包。新导出为 V6，具体流程见[完整包 V6](COMPLETE-WORKBENCH-V6.zh-CN.md)。

## 13. 导入后继续工作

从总览底部“导入工作台包”进入，或在“分享与迁移”选择“导入工作台”。

### 第一步：选择与检查

选择当前 18.0 V5 或 V6 完整工作台包，等待上传和内容检查。支持的文件扩展名为 `.tar.gz`、`.tgz`、`.gz`，但格式仍由内容验证，不能只改后缀。V5 扩展需在接收方人工映射。

有扩展时先在桌面核对版本、来源和权限并确认安装。需要重启时保存其他工作，按界面提示重启 DSH，再从“导入记录”继续原作业。布局预览不代表已发布；会话、附件、扩展数据及内页配置全部恢复和核验后，才出现可打开的工作台。

暂停上传后可重新选择同一文件继续。旧格式或布局参考包不会被当成完整工作台恢复。

### 第二步：内容与位置

检查右侧工作台布局、项目、文件、会话、记忆和任务摘要。可调整接收后的工作台名称与新文件夹名称。

点击“选择目标父目录”，核对完整路径；浏览器中使用“请 DSH 客户端选择目标目录”，回主机确认后继续。目标同名时改名称或位置，无需重新上传。

确认后点击“导入并保持暂停”。

### 第三步：恢复工作台

观察恢复项目文件、对话与附件、任务关联、登记工作台等阶段。作业由 Host 持续处理，重新打开页面可以查看；需要恢复时使用“继续作业”。未开始写入的失败作业可按界面提供的“修改导入位置”处理，已经写入数据的恢复应沿原作业继续。

不要在失败后反复“导入一份”来代替恢复原作业，那会表达创建独立副本的意图。

### 第四步：检查结果

| 报告 | 含义与下一步 |
| --- | --- |
| 数据恢复 | 查看是否已恢复，有无阻断项或未包含内容 |
| 运行环境 | 配置接收方模型、插件和所需工具链；数据齐全不代表环境可执行 |
| 任务状态 | 保持“等待你继续”，按项目和任务选择恢复 |

桌面端点击“打开工作台”。浏览器导入的新工作台需在 DSH 客户端打开，当前浏览器不会自动切换主控。

先检查项目文件和背景/记忆，打开一条历史对话核对内容与附件，再主动发送一轮。最后选择一个需要继续的任务，检查其目标与当前环境后恢复。导入本身不重放历史工具或自动开始任务。

## 14. 一次完整的自检练习

建议使用测试工作台完成以下练习，再处理重要项目：

1. 创建“插件实验室”，关联 `notes-panel`，填写一段项目背景并新增一条已确认记忆。
2. 在同一区域创建三条独立会话，检查各自来源和模式；添加一个可用工具内页。
3. 创建一个小任务，查看 Worker 报告；按实际状态停止或验收。
4. 关闭区域，在总览重新打开项目，确认新区域先显示概览、旧对话和记忆仍可访问。
5. 做一次原版模式往返和浏览器接管/交还，实际输入并发送，记录结果。
6. 导出 V6 包，导入到新的位置，检查数据/环境/任务三类报告。接收方会按本机系统重新检查兼容性。
7. 打开历史会话继续一轮，再主动恢复一个中断任务，检查是否重复执行。

这份清单是可执行教程，不是已经完成的测试报告。反馈时记录插件版本、宿主版本、操作顺序、错误原文、任务/作业阶段及是否可重复。

## 15. 常见问题

**为什么新区域没有自动打开以前所有标签？**

新区域是新的展示空间。项目资料仍在，默认概览让你选择本次需要的对话和工具，避免打开一大组不再需要的界面。

**复制整个项目文件夹能带走全部聊天吗？**

不能。项目目录可携带工作文件、背景与记忆，原生历史和附件仍可能在原机器 Profile 中。完整迁移使用 V6 包；可继续读取当前 18.0 V5 包。

**导入显示数据已恢复，为什么还不能执行任务？**

检查运行环境报告。接收方需要自己的模型连接、插件和工具链；任务默认等待继续。

**关闭标签为什么没有停止 Worker？**

标签是视图。需要停止执行时使用任务的停止入口，并核对实际状态。

**同目录两个区域能同时随意改文件吗？**

它们共享项目文件，不提供隔离。任务分工应避免冲突，必要时先后执行。

**背景说明与磁盘 Markdown 不一致怎么办？**

使用工作台/项目背景编辑入口保存。Markdown 是生成投影，本版不承诺外部编辑双向同步。

**工作台输入区又失效怎么办？**

先确认当前主控是否仍在浏览器；若在则按管理页收回。保存能保存的草稿并记录“工作台 → 原版会话 → 返回”或浏览器操作链路、具体会话与错误。该链路仍是安装验收重点，不以重建会话代替诊断历史会话的问题。

更多技术说明见[项目手册](PROJECT-HANDBOOK.zh-CN.md)、[文档导航](README.md)和[当前验证范围](VALIDATION.md)。
