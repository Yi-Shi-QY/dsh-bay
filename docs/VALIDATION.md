本包实施 18.1 LAN 实时共享工作台方案的以下部分：

- 浏览器主控和 DSH 桌面房主都加入 Host 协作会话，与 LAN 参与者使用同一个会话。会话按使用方持有（LAN 分享、每个浏览器主控视图），停止分享只移除分享的参与者。
- 桌面房主没有可用的插件 WebSocket，改用 DSH 已认证的 `/api/workbench-collaboration/{open,send,poll,close}` 四个路由承载同一套协作帧。
- 共享草稿使用客户端 OT 适配器；消息被 Host 接受后，该会话的共享草稿对所有人清空。
- LAN 参与者按房主的逻辑画布尺寸缩放渲染；草稿里显示其他人的光标和选区；连接恢复中和协作结束时页面只读并显示状态。
- Host 检查：符号链接越界、`file-conflict`、布局控制租约。

已通过的自动化检查：`pnpm check:rc1`、`pnpm typecheck`、`pnpm verify:workbench-package`、`pnpm build`、`pnpm pack:core`，完整回归 170 个文件、1144 项测试。包内 `package.json`、`lib/build-inputs.json` 与 `candidate.json` 的包名、版本、候选 ID 和 DSH 代际一致。上一节记录的 `ENOTEMPTY` 失败在本次多轮完整回归中没有出现，原因未排查。

首次交付的 18.2 包（SHA-256 `68bb2cae…`）在浏览器主控中无法编辑布局和更换内页，已作废。原因与修复：

- 当前区域同时经布局和“共享焦点”两条通道同步，过期的焦点事件把页面切回上一个区域，切回又被发布为新焦点，形成循环（实测两次点击产生 708 条焦点命令）。现在布局是当前区域的唯一来源，焦点只从布局推导后发布。
- 浏览器端连续的布局修改并发提交，Host 写入目录时后一次报版本冲突并回滚；撤回和重做在协作画布上没有提交。现在浏览器端只有一个提交器，一次只发一条；Host 端布局写入按顺序执行。
- LAN 参与者页面在启动时调用 `attach`、`floating-read`，分享网关拒绝，页面显示 `browser-view-not-authorized`。网关现在按参与者自己的关闭凭证接受这两个调用。

第二次交付的 18.2 包（SHA-256 `ba575dd3…`）在用户的真实工作台里仍无法调整区域大小、无法切换内页，访客看不到自定义内页，也已作废。原因与修复：

- Host 保存共享布局前用旧版 v2 布局校验器检查，这个校验器不接受目录型工作台的会话状态。用户工作台 `AAA` 的两个对话类内页按此规则不合法，协作日志里 7 次布局写入全部以“共享布局无效”被拒，页面随即弹回。Host 现在与桌面端保存布局时使用同一个转换，结构检查和项目规则仍由目录写入器执行。
- 访客页面读取 DSH 插件清单需要调用原生插件管理接口，访客无权调用，所有扩展内页显示为“无法读取 DSH 插件状态”。Host 新增 `extension-inventory` 目录操作，只返回 Workbench 需要的身份和状态字段，访客页面改从这里读取。

第三次交付前，用用户工作台 `AAA` 的真实定义确认了旧校验器拒绝、新转换接受；并在临时 DSH 中装入用户的本地扩展 `@local/workbench-snake`，验证浏览器主控可拖动分隔线、在贪吃蛇和功能指南之间切换，访客页面能显示贪吃蛇内页且拖动分隔线后房主页面同步。

在临时 DSH Web profile（`0.2.2-rc.1`，独立 `DSH_HOME`）中用 Playwright 驱动 Edge 验证过：

- 浏览器主控：切换区域、更换内页、添加标签、拖动分隔线、交换区域、关闭内页、撤回、重做，连续快速操作后结果保留；刷新后布局一致且可继续编辑；收回后桌面端可编辑并保存。
- 房主与参与者两个页面：参与者加入后双方显示对方；参与者拖动分隔线、添加内页后房主页面同步；房主关闭该内页后参与者页面同步。

没有做的验证：

- DSH 桌面应用（Electron）中的桌面房主协作通道没有运行过，以上只覆盖 Web profile。
- 第二台设备、输入法组合、两端同时编辑同一份草稿、远程光标的真实位置、画布缩放后的弹出层位置、Host 重启后恢复。
- 参与者页面里浮动工作区、终端和原生会话创建被权限拒绝（控制台有 `remote-access/denied`），这与 18.1 的访客权限一致，没有改动。

方案中没有实施的部分：

- 桌面房主的布局仍通过原有的工作台目录服务保存，再同步进协作会话，不走协作命令，因此桌面端拖动分割条不参与控制租约。
- LAN 参与者的 AI 工具执行仍需房主确认，没有按方案第 7 节取消。
- Area、内页、Session 等结构性操作仍以整份布局提交，不是逐条命令；并发修改时后提交的一方覆盖先提交的一方。
- 参与者“离开跟随”的本地焦点模式没有做，切换内页总是改变共享焦点。
- 桌面端把自己的窗口尺寸发布为逻辑画布尺寸，但桌面端自己不按逻辑画布缩放。

## 重现检查与 CI 边界

```sh
pnpm check:rc1
pnpm test
pnpm typecheck
pnpm verify:workbench-package
pnpm build
pnpm pack:core
```

`verify:workbench-package` 执行指定工作台包服务测试，不等同于检查最终 npm tarball。最终归档仍需按[封包说明](PUBLISHING.zh-CN.md)核对。

`.github/workflows/quality.yml` 当前只有 Ubuntu job，执行 `pnpm verify`（兼容、测试、构建）。CI 尚未自动执行独立 typecheck、封包或三平台迁移，不能把本地手动检查写成 CI 已覆盖。

历史专题的阶段测试数保留原样并明确日期。当前运行时身份以 package.json、`release-compatibility.ts` 和 `check:rc1` 为准，历史 provenance 不随文档整理重写。
