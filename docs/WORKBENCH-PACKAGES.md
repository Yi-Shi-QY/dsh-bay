# 工作台包：导出、导入与扩展兼容

适用于 18.2 文件夹工作台，DSH 依赖为 `0.2.2-rc.1`。本页说明离线包分享与迁移；局域网实时协作使用独立流程。

## 两种导出用途

| 选项 | 适用目的 | 内容与边界 |
| --- | --- | --- |
| 完整工作台包 | 换机器、备份、带着工作进展交接 | 沿用 V6 完整包，包含工作台文件、布局、会话、记忆、任务及通过迁移检查的扩展数据；账号凭据与本机运行环境仍须接收方配置。 |
| 工作台模板包 | 分享可复用的工作方式 | 沿用 V4 `.wbpkg` 容器，包含区域、内页顺序和扩展可迁移配置；可选择携带手动填写的工作台背景。新导出的模板不包含工作文件、会话绑定、模型选择和任务进度。 |

模板的扩展交付方式作为次级选项保留：

- **接收方自行准备扩展**：分享布局与配置。缺少或不匹配的扩展显示为待配置内页，配置留在 Host 导入记录中；安装并授权精确匹配的扩展后，从导入记录恢复。
- **联网获取指定扩展**：锁定版本与内容，从包声明的仓库获取对应制品；需要仓库可达且制品通过校验。
- **随包携带扩展**：携带允许分发的扩展制品；导出前检查依赖与迁移能力，导入时核对身份、权限与实际安装状态。

仅携带背景说明时，选择的是手动填写的工作台整体背景，不包括区域项目背景或 Agent 运行记录。旧 V4 包仍由原有严格校验器检查；这不是 17.x Settings 数据迁移。

## 一个导入入口

在 DSH 的“分享与迁移 → 导入工作台”选择文件。根据文件内容识别 gzip 完整包或 ZIP 模板包，再交给 Host 检查清单、签名、依赖及数据；文件后缀不作为可信判断。接受已有 V5 / V6 完整包及 V4 模板包，拒绝原始诊断 JSON 和退役布局格式。

模板导入需要选择父文件夹和新文件夹名称。Host 检查目录，再安装或复用扩展、恢复配置，最终创建 `.bay/workbench.json`。导入的工作台保持未打开，不切换当前工作台，不把导入工作台写回旧 Settings；项目与会话由接收方重新绑定。重名目录、非法目录名和来自原机器的 Session 绑定会被拒绝。

完整包继续使用现有分阶段恢复作业。模板继续使用可恢复导入事务。统一“导入记录”同时列出两类记录，“查看与继续”返回对应流程。查看记录不会自动批准插件安装；已经批准的事务可在重启后继续。已批准的模板事务固定导入位置，不能在安装中途更换目录。

浏览器主控继续使用已支持的完整包流程，由 DSH 完成原生目录选择。模板导入在 DSH 桌面完成。

## 同名插件如何处理

“同名”按插件包身份判断，而不是显示名称。插件安装在 DSH Profile 中，工作台文件夹没有独立的插件版本环境。

| 接收方情况 | 处理方式 |
| --- | --- |
| 同包名、同版本、同构建，契约与授权检查通过 | 复用已安装插件；仍检查运行注册和配置格式。 |
| 本机版本更高或更低 | 显示包要求版本和本机版本；不自动升级或降级，不尝试未经声明的跨版本恢复。 |
| 版本号相同但构建内容不同 | 按内容身份冲突拒绝复用；不覆盖本机插件。 |
| 插件未安装 | 在包允许的在线或内嵌方式下，由用户确认后安装；自行准备扩展的模板可先保存待配置内页。 |
| 完整包的必需扩展或数据迁移处理器不满足 | 保留恢复作业与检查结果，阻止最终发布，不把缺失扩展数据当作成功导入。 |

要处理版本差异，先在 DSH 插件管理器解决对应 Profile 的插件环境，再继续原导入记录。改变该 Profile 的插件版本可能影响其他工作台。当前没有新增插件多版本并存或跨版本数据迁移协议。

## 验证范围

自动化覆盖真实临时目录发布、保持当前工作台、重复请求与中断恢复、三种模板交付模式、实际离线扩展安装、版本/构建冲突、缺失配置恢复、界面路由与目录选择。浏览器验证使用真实页面组件、Windows Edge 与模拟 Host，覆盖桌面和窄屏。

实际 DSH 安装后仍需用自己的完整工作台与扩展做往返验收。包与验证结果见 [VALIDATION.md](VALIDATION.md)。
