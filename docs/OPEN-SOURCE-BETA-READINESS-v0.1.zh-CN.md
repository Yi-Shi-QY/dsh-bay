# DSH Bay v0.1 公测与开源准备清单

更新时间：2026-11-16（Asia/Shanghai）

本文是 DSH Bay 公测 `v0.1` 的发布门禁。目标不是把当前私有候选仓库直接公开，而是从确认过的代码快照生成一个新的、单初始提交的公开仓库。`dsh-bay@0.1.0-beta.1` 是当前建议的首个公开候选版本，最终包名、版本和仓库地址仍需在快照冻结时确认。

## 发布边界

本轮公测的产品边界应先写死，避免把尚未完成的长期愿景包装成当前承诺：

- 面向懂和不懂 DSH 的用户，提供可逐步积累的工作台、Agent、插件和资产管理能力。
- 用户可以创建或使用工作台，在工作台内组织项目、会话、工具、Skill 和 Agent，并在使用中迭代。
- 熟悉 DSH 的用户可以细致调整工作台并分享；没有 DSH 基础的用户可以从模板和现成 Agent 开始。
- 局域网共享属于公测能力，必须明确房主、访客、权限、断线和数据边界；不能把它描述成云端协作或多人实时编辑服务。
- 公测版本只支持已验证的 DSH 兼容范围：`>=0.2.2-rc.2 <0.2.3`。超出范围的 DSH、跨代数据迁移和跨平台支持不能默认为已支持。

公开产品版本与内部候选版本分开管理：内部 `0.2.2-alpha.18.7` 只作为来源快照线索，不进入公开版本号、公开 README 或公开制品文件名。

## 当前证据与差距

### 已有自动化基线

此前 RC2 工作树已完成以下自动化检查：

- `pnpm typecheck`
- `pnpm test`
- `pnpm check:dsh-dependencies`
- `pnpm check:compat`
- `pnpm check:rc1-history`
- `pnpm build`

最近一次实际回归为 179 个测试文件、1225 个用例通过。当前仓库内的 `docs/VALIDATION.md` 仍记录 1219 个用例，发布前必须重新运行并以唯一的新版本验证记录为准，不能沿用旧数字。

### 尚未形成发布证据的部分

以下项目在当前审计中仍未完成，不能用单元测试或私有封包代替：

- DSH `0.2.2-rc.2` 桌面真实安装、停用、重启和卸载。
- 干净 Profile 启动、重启恢复，以及 Agent 注册后已有会话恢复。
- 第二台设备接入局域网、访客真实发送消息、断线重连和权限拒绝。
- 房主与访客完整工作台流程，包括模板/完整包导入、Agent 过滤和原生 Agent 选择。
- 真实模型长时间运行、错误和中断恢复。
- 至少一个公开支持平台的端到端验收；其他平台要么完成验证，要么在支持矩阵中明确列为未支持。

## P1：公测前必须完成

| 状态 | 项目 | 通过标准 |
| --- | --- | --- |
| ☐ | 真实使用场景模板 | 至少准备 3 个脱敏模板：从零创建、专业 Agent 工作台、局域网共享工作台；每个模板有目标、输入、预期结果和限制 |
| ☐ | 新手路径 | 没有 DSH 开发经验的用户能按 README 在 30 分钟内安装、打开示例工作台并完成一次受控任务 |
| ☐ | 专业路径 | 熟悉 DSH 的用户能定位插件、Skill、Agent、工具和模板的来源，修改后重新导出或分享工作台 |
| ☐ | 数据边界说明 | 明确哪些数据落在 `.bay/`、哪些属于 DSH Profile、哪些会通过局域网发送；示例不得包含真实凭据或对话内容 |
| ☐ | 故障处理 | 覆盖安装失败、版本不兼容、端口占用、访客失联、权限拒绝、导入中断和恢复失败的处理步骤 |
| ☐ | CI 门禁 | Pull Request 至少运行依赖安装、类型检查、测试、构建、兼容性检查和公开文件扫描；发布 tag 额外运行打包与制品检查 |
| ☐ | 问题收集 | Issue 模板、支持渠道、版本字段、环境字段和最小复现要求已上线；公测反馈可以按场景统计 |
| ☐ | 版本策略 | 定义 `beta.1` 到后续 beta/稳定版的兼容和弃用规则；明确哪些数据格式在 beta 期间可能变化 |

## P2：可以在 Beta 后完成

- 跨平台完整矩阵和自动化桌面安装器。
- 更多模板、公共模板目录、模板评分和工作台分享发现机制。
- 更完整的插件开发脚手架、资产版本管理和迁移工具。
- 云端协作、组织权限、审计日志或公共托管服务。
- 将历史内部设计材料整理成公开架构文档和贡献者教程。

P2 不得作为 `v0.1.0-beta.1` 的隐含承诺；如果 README 提及它们，只能放在明确标注的后续路线图中。

## 发布前执行顺序

1. **冻结范围**：选定 RC2 工作树快照，完成 allowlist 和排除清单审阅；确认不包含当前未提交的评审材料、`dsh-superagent/`、临时日志和私有候选制品。
2. **构建公开目录**：在当前仓库之外生成 `dsh-bay-public-v0.1`，只复制公开 allowlist；禁止复制 `.git` 和整个工作区。
3. **公开化改写**：更新版本、README、用户教程、验证记录、发布说明、许可证和治理文件；清除 private staging、内部路径和历史候选叙述。
4. **静态审计**：扫描敏感信息、绝对路径、内部域名、候选目录、测试日志和许可证；检查 Git 索引与 tarball，而不是只检查当前文件夹。
5. **自动化验收**：在干净目录执行 `pnpm install --frozen-lockfile --ignore-scripts`、兼容性检查、测试、类型检查、构建和封包。
6. **人工验收**：按 P0 的桌面、干净 Profile、第二设备和真实模型清单逐项记录证据。
7. **初始化公开 Git**：在公开目录执行 `git init`、添加文件、创建唯一初始提交，再创建已确认版本的 tag；确认 `git rev-list --all --count` 为 `1`。后续开发可以正常增加提交，单提交只约束公开仓库的初始快照。
8. **最终复核**：由至少一名未参与快照整理的人按本清单复核，形成签字记录。
9. **发布动作**：只有 P0 全部关闭后，才执行远程仓库创建、push、GitHub Release 和 npm publish；这些动作分别记录结果和制品摘要。
