## 1. 结论

当前实现已经采用 18.0 的关系模型：区域拥有项目目录，内页拥有独立来源 Session，会话和任务归属持久存在；合并显示保留来源区域定义，关闭内页只移除视图，Bay Agent 任务与视图生命周期解耦。旧 `areaBinding` 仅作为读取兼容字段保留，不再作为新写入模型或区域代表 Session。

需要一起修复三类关系：

1. **项目关系**：区域选择目录；Session 的项目由宿主解析；不能从区域第一张标签推断项目。
2. **来源关系**：内页持有自己的会话或资源来源；切换、移动、复制视图不重绑其他内页。
3. **归属关系**：会话、任务、背景所属区域持久存在；关闭标签或收起布局不能使归属对象消失。

旧提示文案属于同一轮交付范围。按钮、菜单、拖拽预览、禁用原因、空状态、错误、无障碍标签、导入说明和开发文档必须与新规则一致，不能只改可见标题。

### 3.1 已有正确行为应保留

- 对话“添加”入口逐页选择；待选标识独立，选一个页面不批量绑定其他页。
- 同 Session 多视图仍可共享原生历史；“复制视图”不等于创建 Session。
- Host 对跨项目会话写入的拒绝有效，不能为绕过保存错误而放松。
- 浮动转入区域先持久保存再改变位置；Main 保持在既有浮动工作区。
- 资源地址携带会话或父子会话身份时，保留真实来源校验；不能为去除旧区域绑定而删除资源校验。
- Session 目录在关闭标签后仍保存记录；需要补齐区域定义/任务解析，而非删除这些历史记录。

## 4. 建议统一的对象与操作语义

### 4.1 两个位置与一个归属

建议在 `.bay/workbench.json` 内明确持久区域定义，布局引用 areaId。实现可沿用已有 areaProjects/areaContexts/areaMetadata 映射并收敛为一致的定义接口，避免另建一份可独立修改的主数据。

- **项目位置**：区域的根内相对目录及其版本；本机 Workspace 为宿主解析结果。
- **显示位置**：内页当前在哪个区域容器或浮动工作区。
- **业务归属**：Session 的 ownerAreaId、Work Item 的 areaId、相应背景来源；Main 属于工作台。

区域定义不因没有标签或暂时不在布局里就失效。目录、背景、任务仍可按 ID 查询；“不显示”“归档”“删除”分别处理，不能用一个 archived 标记兼任三种含义。

普通移动只更新显示位置。跨同项目区域显示时，按需提示“来源区域：研究”，模型背景继续来自持久归属区域。新建对话时，归属为发起创建的区域。

同一 Session 出现在多个区域，仍只有一个业务归属；不能因聚焦不同视图而改系统背景。浮动里打开根内普通会话时，缺少归属需要明确选择对应区域；根目录 Main 使用工作台背景。根外会话可按已有能力临时查看，但不得静默作为完整工作台包内的项目会话。

### 4.2 布局操作矩阵（推荐方案）

| 操作 | 条件与结果 | 会话/背景/任务 |
| --- | --- | --- |
| 区域新增对话模块 | 每次打开选择已有对话入口，可明确跳转新建；已有候选按项目过滤 | 只设置本内页来源 |
| 新建对话 | 区域已设置项目；使用该目录和所选 Agent 模式 | 新 Session，登记当前区域归属 |
| 打开已有对话 | 项目匹配；已有视图优先激活，无视图则新增；不重定向任意第一张页 | 不改已有归属 |
| 更换本页对话 | 显式菜单操作，选择器作用于确定 tabId，保留草稿关闭保护 | 不改兄弟内页；不让换页成为转移任务手段 |
| 区域内排序 | 始终只改顺序/激活状态 | 身份均不变 |
| 移到另一区域 | 会话/项目资源与目标项目相同；不同项目阻止并提供对应区域入口 | 保留来源及业务归属 |
| 浮动加入区域标签 | 同项目不同 Session 允许；缺来源的内页继续待选择；目标未设目录则先设置 | 不继承第一张标签的 Session；Main 禁止移出 |
| 浮动放入新分屏 | 从已校验来源项目建立新区域项目映射；来源不明时创建待设置空区域或先选择来源 | 保留原 Session，不改 cwd；先原子提交再转移运行实例 |
| 拆出内页 | 新区域引用原项目；搬动该 tabId；原区域即使空也保留 | 不新建 Session，不转移任务归属 |
| 复制视图分屏 | 新 moduleInstanceId，引用相同 Session；新区域默认同项目 | 新视图，原生会话与任务不复制 |
| 新建空区域 | 独立新区域，可待设置目录；“同项目分屏”作为明确快捷方式 | 不自动创建普通会话；背景默认空 |
| 交换区域位置 | 交换布局中的完整区域引用，允许不同项目区域交换位置 | areaId、项目、背景、任务和所有内页作为整体保持关系 |
| 合并显示 | 同项目区域允许；不同项目保留独立容器，支持改为交换位置 | 目标容器显示全部内页，来源定义保留；背景不覆盖，任务不重派 |
| 关闭内页 | 移除视图，最后一个内页关闭后显示空区域 | 不删除 Session，不取消任务，不删除项目文件 |
| 收起/重新显示区域 | 只改变布局可见性 | 通过持久定义继续解析归属 |
| 归档区域 | 明确操作，先处理活动任务和其他有效引用 | 保留历史与目录，禁止默默把任务改派给邻区 |
| 撤销/重做 | 纯尺寸/顺序为布局历史；新增/收起区域等走可恢复操作记录 | 不反向执行模型调用，不重建会话 |

“合并显示”是本稿提出的保守语义：把多个分工的内页集中显示，同时保留原分工。若以后需要把来源区域的职责、背景和任务真正合到目标区域，提供单独的“迁移分工”操作，展示范围及冲突，暂停受影响执行后提交；不能让拖拽自动做这件事。本建议尚未作为已确认产品决策写入上层计划。

实施过渡期，在持久区域解析与任务检查尚未完成前，有任务/会话归属引用的区域合并应明确阻止，避免继续生成悬空引用。这是临时保护，不是最终功能目标。

### 4.3 项目相容性判定

统一由 Host 解析区域项目，校验实际路径、目录版本、Workspace 映射与 Session 真实所属项目。客户端可使用宿主投影预览，提交时再次校验。

- 同项目由宿主规范化后的身份决定，不能只比较显示名、用户输入路径、首个 tab 或两个 undefined。
- 根内链接、Windows 大小写和 junction 继续遵守现有目录归属约束。相同实际目录的别名需要统一登记规则，不能一处按 Workspace 放行、另一处按原始字符串拒绝。
- 空区域也按项目记录判断。无项目不视为“与所有项目匹配”。
- 无项目依赖的根级页面可以移动；Session 页必须有明确来源；项目页只有项目身份也能使用。
- 跨工作台转移不作为普通拖拽扩展：首版拒绝并提示使用完整包/明确导入能力。

## 5. 实现组织与接口调整

### 5.1 一个校验结果贯穿所有入口

建议新增区域操作策略模块和 Host 操作服务，名字可在实现时调整。布局 reducer 保留为纯计算层，不自行推断项目/会话归属。

`previewOperation` 返回允许与否、稳定原因码、涉及的区域/内页、预期版本及影响摘要；`applyOperation` 携带 requestId 和 expectedRevision，重新校验并提交。菜单、禁用 tooltip、拖拽预览、快捷键、Agent API 和最终保存消费相同的规则与原因码。

操作包括移动内页、拆出、复制视图、交换区域位置、合并显示、新建区域、收起/显示区域。区域目录、必要定义和布局在同一 Host 写入边界提交，不先画出成功结果再等自动保存报错。

涉及多个存储的操作使用现有可恢复操作记录扩展：记录准备、提交、完成与身份映射；重试幂等。编排存储与工作台定义无法靠一个文件替换实现共同原子性，必须定义恢复顺序，并在未完成时阻止完整导出。

### 5.2 消除区域 Session 身份

- 清理 `GroupNode`、`AreaNode`、投影/normalization、验证、展示层中的 areaBinding 推断与回退。
- `areaSessionBinding` 改为明确的“当前内页来源”查询；名称、注释和调用者一起修改。
- `retargetBindingArea`、`bindAreaSession` 等具有旧语义的接口改为明确 moduleInstanceId/tabId 目标；旧出口移除或明确拒绝，不暗中批量处理。
- 项目版本、内页 bindingGeneration、任务 Assignment/运行实例各自独立。创建第二个会话不改变整个区域的项目版本。
- 异步创建或选择操作固定目标内页。目标已关闭、重绑、项目已变更则拒绝过期结果；仅激活页改变不能把结果写入另一页。
- 创建 Session 前先校验区域/项目并建立持久请求记录；创建成功、登记失败时保留结果映射，重试继续登记，不能把 requestId 只用在最后一步。
- Control Plane 用 `project`、`sessions`、`modules` 表达事实；如需 focusedSession，仅作为可选当前显示信息。Agent 不再读取代表全区域的 `binding`。
- V2 视觉投影 / V3 文档命名不等于允许迁移 17.x 数据；18.0 的外部格式校验边界保持明确。

### 5.3 插件、资源与运行实例

通用“添加内页”没有明确来源时，Session 插件使用现有选择器。用户从某个对话点击“查看轨迹”“打开终端”“查看此结果”时，动作已携带来源，可直接打开并保留它。

复用键按插件需求构成：工作台 + editorId/scope + project/session 来源 + resource 身份；导航页码/行号与资源身份分开。A/B 会话的同类插件可同时存在。相同 Session 的相同资源可定位已有视图；明确“复制视图”允许多个实例。

文件浏览器改接项目目录服务，支持零 Session 列目录、读文件、预览和错误恢复；单纯把空状态改成“设置目录”不能算完工。会话终端、轨迹、审查、子会话资源继续保持其原生 Session/父子关系，不强行统一为项目页。

保留浮动/区域运行实例稳定身份、草稿关闭保护、资源来源校验、跨窗口控制权和转移时 CAS。Main 根据工作台 Main 身份保护，不能只依赖当前标签显示名称。

### 5.4 Worker、背景与记忆

- Work Item 持久关联逻辑 sessionKey；Assignment 记录执行 Session 映射、项目版本、Agent 模式与运行实例。moduleInstanceId 是可选展示定位。
- 续做先查 Session 目录和原生 Session 可用性；原视图关闭就重新打开视图，不新建会话。只有失效、模式不兼容或显式隔离才新建并记录原因。
- Worker 监视不以标签存在、区域是否可见为有效性条件。换标签、关闭视图、复制、交换位置不触发 cancel。
- 真正的项目变更、任务取消、Assignment 被替代、运行身份变化仍使旧执行失效。
- 背景注入按业务归属，模型调用边界读取最新版本。背景版本变化采用既有 CAS/报告冲突处理，不能简单等同任务消失。
- Main 的区域概览同时能解释未显示但仍持有任务的区域。记忆中的 areaId 仍能解析；合并显示不串写两个区域的背景或记忆。

### 5.5 保存、包和恢复

V5 保持按持久 Session 目录收集，关闭标签不排除历史。新增持久区域定义及归属信息随完整包恢复；导入发布前校验所有区域、会话、任务、内页、资源引用。

定义完整性检查至少包含：区域项目存在/合法、每个会话有可解析归属（或 Main 身份）、视图与所在项目相容、同一 Session 多视图映射一致、Work Item 引用可解析、插件资源来源相符。来源区域不在布局中是合法状态，前提是持久定义存在且状态明确。

浮动普通会话是否已登记必须可核对；根外临时资源明确列为包范围外或阻断依赖，不能报“全部完整”。Main 必须在映射中，即使浮动工作区当时关闭。

轻量布局模板若继续保留，用 `sourceRef` 等明确来源组：同一来源的多个视图映射一次，不同来源分别选择；区域目录仍单独设置。模板只提供布局和声明能力，不替代完整会话迁移。旧工作台包在入口及 Host 服务早拒绝，显示支持格式；检查到旧解析代码不代表应继续暴露旧迁移功能。

## 7. 实施顺序

本次顺序是 18.0 主计划的补充修复阶段，不重启整个 P0—P5。

| 阶段 | 交付 | 验收后进入下一阶段 |
| --- | --- | --- |
| R0：收敛契约与复现 | 固定“区域项目/内页来源/会话归属”；持久区域解析与共用原因码设计；将本轮复现固化为有意义的回归用例 | 明确每种操作影响哪些对象，不存在 UI/API 两套规则 |
| R1：Host 结构操作 | 拆分继承项目、交换完整位置、关闭保留区域；移动/合并预检；原子提交和失败恢复；短期拦截不安全合并 | 操作可保存、重开一致、无半成品区域或悬空引用 |
| R2：会话与插件入口 | 去 areaBinding 推断；统一逐页选择、导航与插件复用；零会话项目文件页；清理错误标题 | 三会话及各自插件不串；新建/续用/复制视图行为明确 |
| R3：编排与业务归属 | 持久 Session 续用；任务与标签解耦；背景/记忆按归属；完成合并显示与来源区域可查询 | 活动 Worker 经移动、关闭、交换、合并显示仍可正确报告；同任务续做不多建会话 |
| R4：恢复与交付 | 模板来源分组、V5 关系完整性、撤销/重做、多窗口、文案/文档回归；构建实验包 | 下述跨层验收通过，提供真实模型手测清单，用户验证后再提交 |

文案随对应阶段落地；R4 做全局漏项检查。若 R1/R2 中间封包，只能明确标为局部修复实验包，不能宣称已达到长期自主编排门槛。

## 8. 验收矩阵

### 8.1 布局与持久化

1. 一个区域建 A/B/C 三个不同会话，各自新增轨迹/终端；从任意页开始添加均独立选择，替换只影响本页。
2. 同项目不同会话中心移动和浮动加入成功；同项目不同区域背景保持独立。不同项目提示准确，提交再次校验。
3. 对已绑定页分别执行拆出、复制分屏、查看关联页分屏、侧栏新位置打开；新区域项目映射正确，保存后重开一致。
4. 两个不同项目区域交换位置成功，项目、名称、背景、任务、插件全部随原区域身份保持。
5. 关闭最后标签保留空区域；零 Session 区域文件浏览器可直接使用。
6. 合并显示保留所有内页来源、原区域背景和归属记录；源区域可查询/重新显示。存在活跃 Worker 时行为符合 R3 契约。
7. 未设置目录、空区域、根级无来源插件、项目插件、缺失 Session、归档 Session、根外临时会话分别覆盖。

### 8.2 生命周期与并发

1. Worker 执行中关闭视图、移动视图、复制视图、切换标签、交换位置；不额外调用取消/派发，不把报告写到别的区域。
2. 关闭 Worker 内页后继续同一个 Work Item，复用原 Session；新建另一 Work Item 才新建 Session。
3. 显式隔离新 Session 后，旧 Assignment 的迟到回调无效；纯显示变化不使有效回调失效。
4. 选择器打开后目标页关闭/重绑，拒绝过期结果；只切换激活页不能把结果写到新激活页。
5. Host 保存失败、项目版本冲突、窗口失去控制权时，不丢失浮动页及其草稿；重试不新增重复区域或 Session。
6. 拆分/合并后撤销重做覆盖完整结构关系；重启恢复与浏览器接管保持同一持久身份。

### 8.3 包、文案与实测

1. 经过多会话、复制、移动、合并显示、关闭内页后导出 V5，在干净 Profile 导入；按逻辑 ID 对比项目、区域、背景、记忆、Session、任务和资源。
2. 来源不在布局中的 Session/Work Item 仍可解析，恢复后能重新打开并继续；未知必需引用阻断发布。
3. 同一来源 Session 的多个视图只恢复一个本机会话；不同来源不被模板恢复合成一个。
4. Main 不因浮动窗口关闭/重建/转移操作改变身份；导入默认无执行。
5. 搜索核对旧提示，结合行为覆盖 tooltip、aria、错误分支、中文/英文、导入和插件空状态；没有问号占位或误导性旧说明。
6. 运行相关类型检查、完整回归、兼容检查、构建及包验证；文档记录自动化与真实模型实测的界限。用户再进行长时间编排、重启、跨机续跑。

本轮隔离复现已转为回归用例：结构操作、Worker 视图生命周期、逐页选择、零会话项目文件、模板来源分组和 V5 任务快照均已覆盖。R0—R4 的自动化门槛已完成；真实模型长时间运行和跨平台实机迁移仍由实验包验收。

## 9. 浏览器与协作交接补充（2026-11-09）

后续核查确认，区域/会话解耦还必须覆盖传输身份与视图实例归属，具体按 [浏览器与局域网重构方案](V18-BROWSER-LAN-REFACTOR-PLAN.zh-CN.md) 执行。上一节“自动化门槛完成”仅指当时的区域操作测试，不代表跨端交接实测完成。

- 工作台启动依据文件定义和登记，不再依据旧 Settings。目录、背景、记忆、任务与包接口统一核验作用范围。
- 浏览器主控和访客均通过非 owner 原生 Peer 访问 Session；访客会话权限按持久 Session/区域归属，不能通过共享项目目录或移动可见标签扩大范围。
- 访客切换内页保留为本地选择；主控的当前区域和当前内页不会被访客选择覆盖。主控结构更新时重新套用仍有效的本地选择。
- 编辑器 root 归属于具体视图。原版对话卸载后迟到的 cleanup/setEditable 不能清空当前工作台输入；会话与 Agent 生命周期继续独立。
- 主控交还不停止分享、不销毁 Main/Worker；导出快照等待原生运行到安全边界，不把页面关闭等同于任务完成。

本次测试新增文件型工作台→接管→范围检查→刷新/交还链路以及真实 HTTP/WS 网关验证。Electron 原版往返、真实模型发送和另一设备续作仍需在最终实机记录中逐项确认。
