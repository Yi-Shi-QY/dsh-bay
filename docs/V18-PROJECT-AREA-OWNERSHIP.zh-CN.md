# 18.0 项目持久化与区域展示空间解耦

日期：2026-11-10（Asia/Shanghai）。状态：项目归属实现与构建验证已完成；真实模型运行和跨平台实机迁移待验证。

实现基线：`0.2.2-alpha.18.0` 当前未提交工作树，保留既有总览、分享迁移、浏览器和插件开发更新。本文记录实现状态与尚未验证的范围，不修改用户工作台数据。

## 1. 本次用户确定的方向

区域是展示项目的空间。关闭区域后，该区域从当前工作台定义和布局中移除；新建区域产生新的区域身份。项目背景和记忆实际保存在项目文件夹内，不能依靠保留已关闭区域维持它们。

新区域关联以前的项目目录时，恢复对该项目背景、记忆、会话和任务历史的访问。用户已选择：**先显示项目概览，再手动打开已有对话和其他内页**。不恢复旧区域身份，不自动打开上次全部标签，不自动继续任务。

这项决定替代初版 18.0 计划中的“同项目目录、不同区域保持独立背景”和“关闭后保留区域作为业务归属对象”。已有多会话、原生历史、任务续用和完整包能力继续沿用，归属改为项目。

## 当前实现与验证

- 工作台定义中的 Project 以稳定 `projectId` 关联根目录内的相对路径；项目定义、背景投影和项目记忆写入该项目目录的 `.bay/`。工作台定义不再持有项目背景的第二份可写副本。
- 布局提交只登记当前可见区域。关闭区域会移除区域映射和区域元数据；Project、会话目录、任务账本及记忆保留。撤销只恢复本次视图状态。
- 重新打开 Project 会创建新的 Area 身份和空布局。画布显示项目概览；历史会话由用户逐个打开为视图，任务不会自动继续。
- Session、Work Item、Assignment 和 Attention 保存 Project 归属。继续任务先重新打开对应 Project，再复用可用的原 Session 并创建新的 Assignment。
- 完整包沿用 V5 文件清单与原生会话快照；根目录递归复制包含项目 `.bay/` 文件，导入预检会校验 Project 身份、背景和记忆文件。
- 旧工作台首次载入时升级可判定的目录、背景、记忆和任务归属。背景冲突会保留为候选；无法唯一归属的项目任务进入阻断待处理状态，不静默覆盖。
- 验证：`pnpm test`（161 个测试文件、1042 个测试通过）、`pnpm typecheck`、`pnpm check:rc1` 和 `pnpm build` 均通过。完整打包、安装后基础验证、真实模型长时运行和跨平台实机迁移尚未在本轮验证。

下文“当前实现与问题证据”表格记录的是**本次实现前的审计基线**，用于说明改动动机，不代表当前工作树仍有这些行为。

## 2. 审计前实现与问题证据

以下为静态代码路径核查，未声称已在真实模型运行中复现所有后果。

| 位置 | 当前行为 | 影响 |
| --- | --- | --- |

| `foundation/area-identity.ts`、`foundation/persistence.ts` | 校验 Session、背景和文件页引用依赖区域存在 | 需要同步变更读取、保存、恢复边界 |
| `host-workbench-access.ts`、`host-workbench-native-access.ts` | 会话范围与文件范围通过区域解析 | 浏览器和已有分享接口也需要按新的项目归属解析 |

结论：当前完成的是区域与单一 Session 的解绑，区域与持久项目资料尚未解绑。

## 3. 目标模型

| 对象 | 持有内容 | 关闭区域后的生命周期 |
| --- | --- | --- |
| Workbench | 根目录、全局背景、Main、项目登记、布局、逻辑会话目录 | 保留 |
| Project | 稳定项目 ID、项目目录、项目背景、项目记忆 | 保留，可由零个或多个区域展示 |
| Area | 区域 ID、关联 projectId、位置、大小、区域显示名、打开的内页 | 关闭即移除，不进入“已关闭区域”集合 |
| Session | 逻辑会话 ID、projectId、创建时目录、模式和原生会话映射 | 保留，内页只是视图 |
| Work Item | projectId、目标、会话关联和持续任务状态 | 保留，可在新区域继续查看或续做 |
| Assignment / Attention | Work Item 和具体执行身份、结果、待处理事项 | 保留；来源区域只作可选历史信息 |

同一实际目录在同一工作台内解析到一个 Project。多个区域可以展示它，使用同一份项目背景和项目记忆；各自的内页、选中状态和排版互不影响。同目录不代表同一会话，也不提供并行修改文件的隔离。

同一项目中需要不同任务要求时，把差异写进 Work Item 的目标、范围、输入和验收条件；不再用持久区域背景分叉同一项目的事实。

项目 ID 与路径分离。目录改名、工作台重新定位通过宿主更新登记与必要的原生会话映射，不能用路径字符串充当永久身份。复制目录导致项目 ID 重复时应识别副本，显式分配新身份，不能把两个实际目录当作同一项目。

## 4. 建议的存储布局和写入职责

```text
工作台根目录/
├─ .bay/
│  ├─ workbench.json          工作台定义、项目登记、区域布局、逻辑会话目录
│  ├─ context/                工作台背景的可读投影
│  └─ memory/                 工作台级记忆与 Main 的整体知识
└─ projects/
   └─ app/
      ├─ .bay/
      │  ├─ project.json      项目 ID、名称、背景正文、修订版本
      │  ├─ context.md        项目背景的可读投影
      │  └─ memory/           项目记忆索引、正文、来源与修订记录
      └─ 业务文件……
```

目录名是建议，实施时固定格式版本和保留路径规则。工作台登记仅保存 `projectId → relativePath` 等关系；不能同时在 `workbench.json` 中维护另一份可独立写入的项目背景。UI 从 Host 合成状态中读取项目数据。

项目背景仍保留人类区与 Agent 区，默认空，按版本提交。Markdown 继续作为可读投影；本次不顺带增加外部 Markdown 热同步。记忆沿用版本、来源、候选/已核验状态及用户编辑能力。

所有写操作仍经过同一宿主边界。跨工作台定义和项目文件的修改使用持久操作记录、幂等 requestId 和故障恢复；原子替换单个文件不能冒充多个文件的整体原子提交。

原生活动会话日志仍由 DSH 持久化服务管理，编排账本仍由 Host 管理；不为了“资料属于项目”复制第二套活动日志。完整工作台包负责把项目资料、原生历史、附件与任务快照一起迁移。

**重新关联目录恢复完整历史的前提是当前工作台仍有原生身份映射，或通过完整包恢复了它。** 单独复制项目文件夹可以携带背景、记忆和业务文件，不能据此宣称完整原生会话与任务运行记录也已迁移。

## 5. 操作行为

### 5.1 新建、关联和关闭

1. 新建区域产生新 areaId；选择项目目录后，由 Host 识别或创建 Project。
2. 已有项目展示概览，包含项目名称、目录、背景摘要、记忆、历史会话、任务和打开内页入口。展示概览不调用模型、不创建 Session。
3. 打开已有会话仅创建视图；同任务续做明确使用 workItemId，并优先续用原 Session。
4. 关闭区域移除布局、区域定义及区域专属视图状态；清理浮动状态与插件中对已删除区域的非历史引用。项目、会话、任务、背景和记忆继续存在。
5. 保留关闭时的未保存草稿处理。显式撤销可以恢复本次布局操作，这是有限撤销历史，不是长期“已关闭区域”清单；撤销不回滚项目背景或任务执行。
6. 最后一个区域关闭后展示无区域的工作台空状态。当前 V3 文档要求有根 Area，实施时必须调整为空布局或使用不持有业务区域身份的空壳，不能悄悄创建替代区域使计数永远非零。

沿用用户此前的操作边界：真正运行或启动中的关联执行先停止/等待，再允许关闭；等待人工输入、已停止、已完成、已失败不能仅凭历史记录阻止关闭。这个检查是可单独调整的产品操作策略，不能再靠区域存在性维持执行身份。若后续开放“关闭展示、后台继续”，也无需再改变归属模型。

### 5.2 切换目录、合并和移动

- 区域换绑只改变展示项目，不更改历史 Session 的 projectId/cwd，不把旧项目背景带到新项目。先处理该区域已有内页和草稿，完成后显示新项目概览。
- 同项目区域合并时移入内页、移除来源区域；项目背景和记忆只有一份，无须保留“来源区域”承载它们。
- 不同项目区域继续保持独立容器，避免把项目限定的内页混放；交换区域位置不改归属。
- 内页移动/拆分/浮动保留显式 Session、Project 或资源引用。项目文件页使用 projectId，替换现有 `projectAreaId`。
- 同一项目两个区域并存时，关闭一个不关闭另一个，修改项目背景在后续状态同步和模型调用边界中可见。

### 5.3 项目概览与工作台总览

- “区域与内页”只列当前存在的展示区域，不显示“已关闭”“重新显示区域”。区域计数取当前布局。
- 单独列出项目；未被区域展示的项目提供“在新区域打开”，创建新 areaId 并显示概览。
- 新区域的自动内容仅为项目概览。历史对话、文件、轨迹、审查等通过概览或添加内页入口手动打开。
- “编辑区域背景”改为“编辑项目背景”，展示项目名称和共享影响；未关联项目时引导关联目录，不持久新增区域背景。
- 关闭区域、移除项目登记、删除磁盘目录保持不同操作。本次区域关闭不包含磁盘删除。

## 6. Agent、背景、插件及完整包联动

### 6.1 Agent 与背景

- Main 持续使用工作台根目录，读取工作台背景与项目概览；区域只用于查找呈现位置。
- 普通 Session 与 Worker 按自己的 projectId 读取项目背景和相关记忆，即使原区域已关闭或换绑也不改变来源。
- Work Item、Assignment、Attention 与上下文投影增加项目身份；areaId 降为可选展示定位/历史来源，不再作为执行存续条件。
- 执行校验保留项目身份与目录版本、Session、Assignment、运行实例、重复请求和迟到回调处理。区域位置变化不等于项目变化。
- Worker 对项目记忆提交候选；Main 与用户核验和整理。按项目去重检索，共享目录的两个区域不会重复存储同一份知识。
- 背景生成仍由独立单轮服务承担。项目背景收集该项目在所有展示区域/浮动页中的相关内页，按来源去重；不能只读当前区域，也不默认把未打开的全部历史对话纳入提示词。读取范围、截断和失败保持可见。
- 工作台背景生成需要覆盖已登记项目，即使没有任何区域正在展示该项目。交互偏好中的提示词、工具说明和字段名称同步更新。

### 6.2 插件与浏览器

项目插件使用 projectId，Session 插件使用具体会话，区域插件状态仅用于视图。同步更新 SDK、开发技能、模板、目标发现和离线包资源声明，避免新扩展继续把 areaId 当持久项目身份。

桌面、浏览器和已有协作接口读取同一 Host 投影。已有访问范围要显式映射到项目/会话；不能仅因两个区域共用目录就暗中扩大原有授权。已关闭区域的订阅和展示定位需要释放，后台会话不随视图销毁。

### 6.3 完整包与格式

导出按持久项目登记、逻辑会话目录和任务关系收集。零展示区域的项目仍进入完整包；项目内部 `.bay` 文件不得被当作缓存或插件制品排除。包内同时保存仍存在的区域布局和独立项目资料。

发布导入结果前校验项目文件、背景/记忆版本、会话与任务的 projectId、附件和插件资源。复制导入使用独立本机映射，恢复数据不启动模型和任务。

需要提升工作台定义、项目定义和相关协议的 schema，并为完整包声明必要能力/格式修订。旧读取器必须明确拒绝无法理解的新归属，不能忽略 projectId 后宣称成功。具体是否提升外层 V5 版本，由实现时的解析兼容性检查确定，不能复用同一版本暗中改变必要字段含义。

## 7. 当前 18.0 数据整理

这是对当前 18.0 实测数据的整理，不是重新引入 17.x 兼容。不能直接清空 `areaDefinitions`、`areaContexts` 或把同目录的多个背景相互覆盖。

1. 先备份定义、记忆索引、编排状态和身份映射，写入可恢复升级作业；暂停与升级冲突的新写入和派发。
2. 结合现有目录映射、会话创建路径和任务执行记录建立项目集合；即使旧项目已不再绑定任何区域，只要仍被会话/任务引用就要纳入。
3. 同实际目录只创建一个项目。背景完全相同则去重；不同背景分别保留来源与版本，形成待整理项，不能任意取最后一份。发生冲突时，模型不把冲突候选自动当成已确认项目事实。
4. 记忆按来源项目迁入项目目录；工作台级记忆留在根目录。区域曾换绑、来源无法唯一判定的条目保留在升级待整理记录中，不能猜测归属或丢弃正文。
5. 会话优先以原持久路径归属项目；任务结合原 Session/Assignment/checkpoint 归属。不能使用区域当前绑定路径覆盖旧任务的工作目录。
6. 未绑定目录但已有背景/记忆的旧区域，内容保留到可查看的待整理记录，后续由用户指派项目；不为保住内容继续显示幽灵区域。
7. 校验所有引用后，仅保留当前布局区域。旧区域 ID 可以留在迁移来源和历史事件中，但不能再是运行依赖。
8. 重试沿用升级身份映射；不重复创建项目、Session 或任务，不改写历史自然语言与历史事实。

## 8. 实施顺序与验收

| 步骤 | 交付 | 关键门槛 |
| --- | --- | --- |
| P1 | Project 身份、目录内元数据/记忆、Host 服务、可恢复升级 | 关闭布局之前已能独立解析全部项目与历史归属 |
| P2 | Session、Work Item、Assignment、背景注入、项目插件按项目解析 | 原区域换绑/关闭不使旧会话读错背景，不使历史任务失去归属 |
| P3 | 真正关闭区域、空布局、项目概览、总览分类与文案 | 新区域新身份，同目录恢复资料且只自动显示概览 |
| P4 | 桌面/浏览器、完整包、SDK 和文档同步 | 无可见区域的项目仍完整导出/导入，插件来源正确 |

必须覆盖：

- A 区域绑定 app，写背景和带来源的记忆，建立多个会话和任务；关闭 A 后重新打开工作台，不再出现 A 或“已关闭区域”。
- 新建 B 绑定 app，B 与 A 的区域身份不同，但 projectId 相同；默认只有项目概览。手动打开历史会话保持原 Session，继续原任务优先续用原会话。
- 两个区域共享 app，背景和记忆同步；关闭一个不影响另一个。位置、选中内页和区域名称保持各自独立。
- A 从 app 换绑 research；app 的旧会话/任务仍读取 app 背景，任何迟到报告都不写入 research。
