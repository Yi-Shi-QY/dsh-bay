# 18.0 项目持久化与区域展示

更新日期：2026-11-11。项目模型已随 `8e35cff` 提交，当前功能基线 `ab2a7d8`；原设计与实施前审计见[历史快照](archive/2026-11-11/V18-PROJECT-AREA-OWNERSHIP.zh-CN.md)。

## 当前归属规则

| 对象 | 持久内容 | 关闭区域后的结果 |
| --- | --- | --- |
| Workbench | 根目录、全局背景、项目登记、逻辑会话目录、Main | 保留 |
| Project | 稳定 projectId、相对目录、项目背景与记忆 | 保留，可由零个或多个区域展示 |
| Area | areaId、展示项目、内页与布局 | 从当前定义与布局移除 |
| Session | 逻辑会话身份、所属项目、创建目录、模式及本机映射 | 保留，关闭内页只释放视图 |
| Work Item | 所属项目、目标、原会话和任务状态 | 保留，可从新区域继续 |
| Assignment / Attention | 具体执行、报告、待处理事项 | 保留，区域只作显示定位或历史来源 |

同一真实项目目录在同一工作台中对应一个 Project。多个区域展示它时共用背景、记忆和历史，各自保留内页与布局。任务的不同目标写入 Work Item，不通过区域分叉项目知识。

## 文件与版本

- 根目录 `.bay/workbench.json` 使用 schema 2，保存项目引用与 `projectModelVersion: 1`。
- 项目 `.bay/project.json` 使用 schema 1，保存 `projectId`、名称、结构化背景及可选冲突候选。
- 项目 `.bay/context.md` 是背景投影；项目记忆位于同目录的 `.bay/memory/`。
- 工作台级记忆仍在根目录 `.bay/memory/`。原生对话和编排活动日志继续由 Host / DSH 管理。
- Host 从项目文件合成 UI 快照；`areaContexts` 等旧字段可能作为投影或兼容接口存在，不是另一份可独立写入的背景来源。

目录关联和真实路径验证由 Host 执行，`.bay` 不能作为普通项目目录。复制项目文件导致 ID 重复时当前实现会拒绝并报告，不自动把副本当原项目，也不声称已提供任意目录副本自动修复向导。

## 常用操作

1. **新建区域**：产生新 areaId；关联目录后由 Host 查找或创建 Project。
2. **重新关联原项目**：显示项目概览，用户再打开历史会话和其他内页；不恢复旧区域身份或整组标签，不自动执行任务。
3. **关闭区域**：移除该展示空间；文件、背景、记忆、会话与任务历史保留。关闭最后一个区域允许空布局。
4. **关闭限制**：启动中或真正运行的关联任务先处理；等待输入、停止、完成或失败记录本身不应阻止关闭。
5. **切换项目**：先处理当前内页和未保存状态，只改变展示关联；旧会话 cwd、项目背景及任务归属不被改写。
6. **移动/合并内页**：保留明确的 Project、Session 或资源来源，按目标项目兼容性检查；切换活动标签不能改绑其他标签。
7. **继续任务**：使用明确 workItemId，必要时先在新区域打开所属项目；优先续用原 Session，执行尝试使用新的 Assignment。

撤销布局操作只恢复有限的视图历史，不回滚项目背景或执行。区域显示名称与磁盘文件夹名称相互独立。

## 早期 18.0 数据整理

`host-workbench-projects.ts` 将可判定的旧区域目录、会话、背景与记忆整理到项目模型；目录服务保存原工作台定义备份及恢复写入记录。背景冲突保留候选，无法唯一归属的正文保留待整理信息；任务归属整理由 `host-workbench-task-projects.ts` 处理。

这是 18.0 文件型数据内部的升级，不是对 17.x Settings 或旧格式完整包的兼容。不要手动清空旧 area 字段来模拟升级，也不要把所有同目录背景覆盖为最后一份。

## 完整包与历史恢复

完整包沿用 V5；零展示区域的项目仍按持久登记进入导出，项目内部 `.bay` 文件不作为缓存省略。导入校验项目文件、会话/任务引用，重建本机映射并保持任务等待用户。

只复制项目文件夹可以带走业务文件、背景和记忆，但不能带走仍位于原 Profile 的原生会话、附件或活动任务账本。重新关联后找回完整历史的前提是本机仍有映射，或已从完整包恢复。
