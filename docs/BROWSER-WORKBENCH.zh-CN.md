# 18.0 浏览器工作台与局域网协作

更新日期：2026-11-11。当前功能基线 `ab2a7d8`。本文汇总现行实现；最初计划、阶段差异与故障证据见[原始记录](archive/2026-11-11/V18-BROWSER-LAN-REFACTOR-PLAN.zh-CN.md)。

## 访问同一个工作台

浏览器、桌面与访客访问同一 DSH Host 的根目录、项目、会话和任务，不复制一份浏览器专属工作台。入口通过独立目录服务解析文件型工作台，失败时报告目录或定义错误，不回退旧 Settings 工作台。

| 身份 | 作用 |
| --- | --- |
| 桌面主控 | 本机操作当前工作台，提供原生目录选择及恢复入口 |
| 浏览器主控 | 接管同一工作台的普通写操作；同一租约只允许一个活动页面 |
| 局域网访客 | 按分享模板与明确范围协作，生命周期独立于主控窗口 |

浏览器主控继承桌面的扩展许可和内页可见性配置；不能套用访客裁剪规则导致原有内页全部不可用。底层 Remote Access 的 owner 配置和 Bay 的主控租约仍是两层检查，不能只凭连接身份判断可以写入。

## 接管与交还

1. 桌面准备保存状态与浮动工作区交接，Host 建立待接管身份。
2. 浏览器兑换身份，读取目录快照并检查必要服务，恢复视图后确认 ready；失败则恢复桌面控制。
3. 15 秒心跳续期，90 秒失联阈值；旧代次和迟到写入不能重新激活已收回控制。
4. 主动交还先处理保存状态，再撤销页面身份并恢复桌面。强制收回优先使旧身份失效。

浏览器进入和离开是视图交接，不删除 Main / Worker，也不因交还停止已授权后台任务或局域网分享。

## 直接关闭标签页

`pagehide` 发出 suspend 信号后进入 10 秒刷新宽限期。收到关闭信号且没有重连时，Host 到期释放控制；默认 2 秒桌面查询间隔下，通常约 10—12 秒开始恢复。刷新可以继续同一租约。

宽限期内主动收回会立即处理，已关闭视图接受幂等收回。自动恢复与手动收回共享进行中的操作，避免重复点击互相打断。

关闭通知只在载荷不超过 48 KiB 时携带浮动快照；超限或 Beacon 失败时优先保留小型关闭信号并尝试 keepalive 补偿。断网或进程强杀无法保证通知必达，仍需失联处理或明确强制收回。界面提示使用已保存状态，不能承诺未提交内容全部保存。

## 协作范围

审阅模板用于查看，协作模板允许在已有普通/Worker 会话发消息；Main 发送默认不开放，需单独授权。文件与结构操作按声明范围处理；访客选择标签等临时视图状态不修改主控布局。

Host 对请求、原生会话资源与后续工具执行做范围检查，访客消息进入下一轮队列。未知作用范围的动作进入主控确认；工具守卫、撤销与子任务传递已有自动回归，但不是对任意外部 Runtime、未知插件或真实 LAN 设备的全面验收。

## 完整包

浏览器可发起导出并流式下载；导入上传到 Host 后，由 DSH 客户端确认主机父目录，再由浏览器继续作业。后台作业不依赖页面一直打开，重新进入后按作业身份恢复进度。

导入完成的新工作台不自动接管当前浏览器，任务仍待用户继续。主控租约、分享令牌和一次性目录许可不打包。桌面新导入使用独立范围，不受另一个工作台正在浏览器主控的状态牵连。

## 代码与验证

主要入口为 `host-workbench-access.ts`、`host-workbench-native-access.ts`、`host-workbench-owner-gateway.ts`、`host-workbench-share-*.ts`、`host-browser-window-controller.ts`、`client/browser-window-controller.ts` 与 `workbench-reclaim.ts`（均在 `packages/workbench-core/src/`）。

已有真实临时工作台、HTTP/WS 网关与 Chrome 生命周期验证覆盖直接关页、刷新、主动收回和大载荷关闭信号。界面恢复最后一段、原版/工作台往返后的真实发送，以及跨设备与多浏览器流程仍需安装验收。最新整版验证见 [VALIDATION.md](VALIDATION.md)。
