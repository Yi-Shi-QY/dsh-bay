# DSH Bay 18.0 浏览器工作台与局域网协作重构方案

确认日期：2026-11-09。基线：当前 main，768dd4c 及已有未提交的 18.0 成果。保留现有成果，不迁移 17.x 数据，不升级 DSH 依赖代际。完成实验包后由用户基础验证，再提交代码。

## 1. 目标和产品契约

桌面、浏览器和局域网访问同一个 Host 管理的工作台。目录、区域项目、多会话、背景、记忆和任务均沿用 18.0 模型；完整包负责迁移，分享负责在线协作。

| 项目 | 确定行为 |
| --- | --- |
| 浏览器 | 当前工作台完整操作者，包括布局、区域、背景、会话、记忆、任务和包作业 |
| 主控 | 同一工作台在桌面和一个浏览器页面之间独占交接；其他工作台不受影响 |
| 访客 | 独立于主控，可并存；默认查看并在已有普通/Worker 会话发消息 |
| 授权 | 启动选择审阅/协作及额外范围；运行中可收紧/踢出；扩大长期权限需重新分享 |
| Main | 默认可查看不可发消息；主控可在分享启动时单独授权发送 |
| 执行 | 访客驱动的 AI 工具及子任务继续受分享权限约束，越界操作待当前主控确认 |
| 包 | 浏览器流式下载/上传，导入由 DSH 选择主机目标目录，浏览器继续 |
| 交还 | 主动交还、关闭或失联后桌面恢复；正常交还不停止分享 |
| 重启 | 旧凭证失效，分享需重新开启；已有数据和任务按既有流程恢复 |

## 2. 宿主与主控

目录服务独立于 Bay Agent 初始化；`.bay/workbench.json` 是定义权威，本机登记保存位置和原生身份。浏览器准备、分享启动均查此权威。18.0 失败不得回退旧 Settings。

统一访问服务负责身份、权限、作用范围和主控归属；文件、会话、编排、包仍由原领域服务执行。宿主生成 WorkbenchAccessContext，不信任客户端自报角色。bootstrap 返回限定工作台快照、版本、能力、主控和诊断。请求与返回列表/订阅/附件均按范围校验。

写入携带 requestId，已有对象携带 expectedRevision；结果区分提交、冲突、拒绝、待确认。会话消息明确 Session、内容和附件，由宿主记录来源和接收顺序，重复请求不得重复执行。

接管：桌面 flush 并准备浮动状态 → 兑换身份 → 文件快照/目标定义/必要服务/浮动恢复检查 → Host 确认主控。未绑定区域正常显示待设置；失效会话单独报错，不创建替代会话。失败恢复桌面。

交还：flush → 撤销旧主控代次 → 桌面恢复。强制收回先撤销权限。原版 Session 写入口也执行主控限制；仅隐藏 UI 不够。桌面始终可收回、停止分享、处理主机目录选择。

15 秒心跳、90 秒失联；pagehide 进入 10 秒重连宽限，刷新复用租约；明确交还立即执行。一个租约只有一个活动页面；重复标签不能抢主控；旧页面/旧心跳不得复活。视图释放不得停止已授权后台任务或销毁 Session。

## 3. 协作和执行

分享使用独立访客身份和生命周期，不作为浏览器主控。审阅只读；协作增加已有普通/Worker 消息。额外权限分别为 Main 消息、指定区域/目录文件读取/编辑、布局、背景和任务。正式记忆修改由主控处理具体请求。访客不允许包、凭据、全局设置、安装或分享管理。

会话附件随会话访问权，不授予任意项目文件访问权。共享目录的区域分别授权。HTTP/WebSocket 同一授权规则；明确允许的操作才能转发。校验参数、对象归属、后续流消息、返回数据和订阅。内部上游凭证不是访客权限；未知插件没有默认执行能力。

权限收紧立即影响后续请求/订阅；踢出/停止撤销连接和未开始请求。正在执行的访客操作请求取消，报告实际结果，不承诺回滚已经完成的修改。

消息通过原生服务，不拼写日志。按 Session 排序与 requestId 去重。忙碌会话中的访客消息排到下一轮，不混入当前高权限执行。开始前重新核验。使用执行前检查及单调守卫限制文件/布局/背景/记忆/派发等工具；Main 消息许可不意味着全面管理许可。子任务、转发及 Runtime 继承范围。终端/脚本/未知作用工具需主控确认。未验证权限传递的外部 Runtime 不开放访客驱动执行。

一次性批准绑定执行、参数和对象版本，执行后失效，不扩大长期分享权限，访客不能自批。

## 4. 界面与包

使用现有画布和浮动工作区，Main 保持原有持久标签。以 capability 决定操作入口，不以 browserView 一刀切隐藏。区域根内目录由 Host 列举/创建；根外位置交 DSH 选择。

访客切标签、滚动、聚焦和展开浮动区都是本地视图状态，不写共享布局。只有授权的结构修改写入定义。

会话身份/执行生命周期与界面实例独立；各视图持有自己的引用，重新进入重新取得有效的输入组件和服务。必须真实验证工作台→原版点击→工作台，以及浏览器接管/刷新/交还后的输入与发送。

Host 在根外生成归档，受控流式下载；上传进入 Host 暂存，DSH 选择父目录并签发该作业许可。页面刷新不终止作业，按 ID 恢复进度。快照期间阻止冲突写入并明确提示。导入后待继续，不自动执行/接管。租约、令牌、一次性许可不进入包。

## 7. 实现契约与代码定位

| 边界 | 实现 | 保证 |
| --- | --- | --- |
| 权威定义 | `host-workbench-directory-service.ts` / `host-workbench-directory.ts` | Bay Agent 未启动时目录仍可用；宿主串行提交 |
| 访问身份 | `workbench-access-contract.ts` / `host-workbench-access.ts` | Host 签发访问身份，校验工作台、区域、Session、真实路径、权限版本和主控代次 |
| 主控生命周期 | `host-browser-window-controller.ts` / `resolve-browser-window-view.ts` | 准备→兑换→单页连接→就绪；刷新宽限、心跳、交还、强制收回 |
| 浏览器传输 | `host-workbench-owner-gateway.ts` | 独立本机 origin，内部上游凭据，页面连接证明，流式转发公开工作台接口 |
| 访客传输 | `host-workbench-share-gateway.ts` / `host-workbench-share-session.ts` | 独立访客生命周期；同源校验、明确路由集合、权限收紧、连接撤销 |
| 原生会话与执行 | `host-workbench-native-access.ts` | 非 owner Peer、原生消息队列、历史及附件归属、控制流过滤、工具守卫与执行来源 |
| 输入组件归属 | `client/native-composer-ownership.ts` | 旧界面的 cleanup 和 editable 状态不能干扰当前编辑器 |
| 包作业 | `host-workbench-complete.ts` / `WorkbenchCompletePackagePanel.tsx` | 作业持久化、传输续接、目录许可、身份限定下载 |

工作台目录接口：`POST /api/workbench/directory/v1`。`snapshot` 返回文件快照及 `access` 启动信息。修改请求包含 `requestId`；结构修改和目录绑定包含 `expectedRevision`。浏览器只能提交当前工作台定义；顶层 Profile 替换被拒绝。桌面批量替换也会逐个核验受影响工作台，不能绕过主控或快照锁。

会话消息仍调用原生 `session/prompt`，保留 DSH 请求标识、附件和队列语义。原生非 owner Policy 决定可调用接口和资源；Host 再校验 Session/附件真实归属。会话控制流过滤 baseline 和增量，不能返回整个 Profile。未经适配的插件接口不自动获得访客权限。

待确认操作使用 `POST /api/workbench/access/v1` 的 `pending` / `answer`。只有当前主控可回答；许可绑定工具执行 token、操作参数摘要、工作台定义版本和所有来源的权限版本，工具结果产生后失效。权限撤销不声称回滚已完成修改。

包接口：`POST /api/workbench/complete/v5` 管理作业；`/upload` 接收分片，`/download` 以短期作业许可流式返回归档并支持 Range。返回值不暴露宿主暂存绝对路径。桌面选目录许可绑定特定上传与导入请求。租约、分享凭据、页面连接证明、传输下载许可属于本机运行态，不进入包。

## 9. 本轮实现收尾

- 区域范围的目录定义修改会把已验证的 reaId 一路传到最终写事务，隐藏区域字段会在访客编辑后保留。
- 浏览器主控的原生 Remote Access 页面基线使用 owner principal；Host 仍独立校验交接租约，未完成交接时实际写入继续拒绝。
- 浏览器端相关请求和布局标识使用浏览器安全 UUID，在普通 HTTP 局域网页面没有 crypto.randomUUID() 时仍可初始化；访问凭证仍只由 Host 生成。
- Windows 8.3 短路径会先通过 native realpath 统一，再进行 Session 工作目录和工作台根目录的归属检查。
- 本轮自动化结果：153 个测试文件、973 项通过；类型检查、RC1 兼容检查、工作台包校验和构建通过。真实模型长时间运行、跨平台导入和 LAN 实机仍待用户实测。

## 10. 本轮浏览器容器内页修复

2026-11-09：确认“未开启局域网分享时，浏览器工作台中的已有扩展内页显示‘此扩展未允许在 Workbench 中使用’”的根因是浏览器主控快照裁剪了桌面端的全局 `extensionConsents` 和 `globalHiddenEditorIds`。这不是 LAN 访客权限触发，而是本地浏览器 owner 视图没有继承完整的 Workbench Profile 投影。

修复后，`browser-owner` 快照保留桌面端已经确认的扩展许可和全局内页可见性；浏览器设置投影继续保留这些字段，扩展目录可以按与 DSH 客户端相同的许可状态恢复已有容器内页。`lan-guest` 快照仍不包含这些 Profile 级字段，保持分享视图与本地完整操作者视图分离。

定向回归覆盖 Host owner 快照、浏览器设置投影、扩展目录许可恢复、原生访问和浏览器窗口网关；类型检查、构建和实验包已重新生成。真实浏览器实机和局域网设备验证仍按交付清单由用户基础验证完成。


## 11. 2026-11-10：关闭浏览器标签页后的收回修复

用户实测发现：直接关闭浏览器工作台标签页后未正常恢复桌面，再点客户端“收回”也无法完成。通过真实文件型工作台、Host 目录/访问服务和两端控制器复现，确认以下原因：

1. 正常确认交还走完整桌面恢复，而 `closed` 分支只恢复浮动数据，没有刷新工作台定义及原生会话，也没有进入输入就绪检查。
2. 10 秒重连宽限期到期后，Host 已把浏览器记为 `closed`；此时客户端仍可能保留上一次 `ready`，主动收回会被 Host 以 `browser-view-not-ready` 拒绝。
3. 关闭通知与完整浮动快照被放进同一个 Beacon。浮动协议允许 512 KiB，但浏览器 Beacon/keepalive 通常只有 64 KiB 队列额度；原实现忽略 `sendBeacon` 的 false 返回值。
4. 自动恢复已经开始时再次点击收回，可能建立新操作代次，打断原恢复并重复刷新。新增交叉时序回归锁住此行为。

修复后的契约：

- 刷新或关闭触发 `suspend` 后保留 10 秒刷新宽限期。未重连则由 Host 释放控制，桌面下次状态查询进入统一的“恢复浮动状态→刷新目录与会话→检查可见输入组件”流程。默认 2 秒查询间隔下，正常自动恢复约在关闭后 10—12 秒开始。
- 宽限期内用户主动收回会立即结束宽限期，不再等待已退出的页面确认。Host 已关闭的视图也接受幂等收回请求。
- 自动恢复和主动收回共享正在执行的操作；用户重复点击不会建立第二次恢复。旧页面重连、迟到回调和已经取消的宽限期不能重新取得控制。
- 关闭后恢复标记 `reclaimProgress.recovery = 'page-closed'`，告知用户使用已保存状态；不能声称页面退出前的所有未提交修改都已保存。
- 只有不超过 48 KiB 的关闭载荷尝试携带浮动快照。载荷过大、序列化失败或 Beacon 入队失败时，优先发送小型关闭信号；必要时用同源 keepalive 请求补偿。不能送回完整浮动状态时保留来源副本及已有不完整提示，不清空为新工作区。
- 不支持离线或浏览器进程强杀时必达通知。若全部关闭通知丢失，仍按既有 90 秒心跳失联与明确强制收回流程处理；本次不把未确认保存的失联视图静默当成完整交还。
- 局域网访客生命周期、后台 Agent 和工作台持久数据不由这次视图关闭结束。
