## 1. 目标与已确认边界

工作台拥有根目录，区域关联根内项目文件夹，内页绑定具体会话；Bay Agent 使用根目录，持续管理任务和专属记忆。完整包携带目录、文件、历史、资源、背景、记忆、插件与任务关系，接收方导入后配置本机环境即可继续。

| 项目 | 决策 |
| --- | --- |
| 工作台 | 选父目录，新建独立根文件夹 |
| 区域 | 选根内已有子目录或新建；允许多个区域共享目录 |
| 会话 | 一个内页绑定一个 Session；区域允许多个 Session |
| Main | 工作台创建时建立唯一持久会话，使用根目录，仍在已有浮动工作区 |
| 任务 | 同任务优先续用会话，新任务另建；失效、模式不兼容或明确隔离时另建 |
| 背景 | 默认空，UI/API 编辑，Markdown 为结构化数据的可读投影 |
| 记忆 | 根内持久文件，记录来源和版本，用户可查看修改移除 |
| 完整包 | 默认全部工作文件，包括隐藏文件、Git 和依赖；排除项显式记录 |
| 平台 | Windows/macOS/Linux 互导；数据恢复与环境就绪分别展示 |
| 执行 | 导入不运行模型、工具、计划任务或安装脚本，等待用户继续 |
| 旧数据 | 不适配旧结构/旧包；明确拒绝并保留原数据，不静默重置 |
| 迁移入口 | 完整包；直接复制活动根目录不承担完整会话迁移 |

不接 IM、不迁移 OS 进程、不做外部 Markdown 热同步、不引入自动 Git worktree 隔离。

## 2. 目录与数据模型

工作台有稳定 ID；区域有稳定 ID 和根内相对路径；会话有可迁移标识、所属区域/Main 身份及本机 Session 映射；内页引用具体项目、Session 或资源。Work Item 是持续任务，Assignment 是一次执行尝试。

根目录绝对位置、原生 Workspace/Session ID 属于本机登记。显示名、文件夹名、稳定 ID 分离，改显示名不移动文件。共享目录可以复用 Workspace，背景、任务归属仍按区域管理；共享目录不提供并发文件隔离。

```text
工作台根目录/
  .bay/
    workbench.json    定义、区域、布局、背景、会话目录、插件配置的唯一来源
    context/          工作台和按 areaId 区分的区域 Markdown 投影
    memory/           索引（版本/来源/验证状态）和主题 Markdown 正文
  projects/           示例业务目录，名称不强制
  outputs/
```

Settings 只读取 Host 投影，不保留第二份可写主数据。活动日志继续由原生 Session Persistence 管理。编排 NDJSON、checkpoint、运行状态保留 Host 存储；导出时物化快照，不双写活动会话。Profile 保存本机登记、身份映射、连接/凭据、窗口偏好和运行实例。

Host 统一串行写入、requestId 幂等、expectedRevision 冲突检查、临时文件/原子替换和可恢复操作记录；多窗口经过同一服务。

- 新建工作台展示完整目标目录；创建目录、定义、Main；重复请求不重复创建。
- 区域选/建目录不创建普通会话；预设未绑定区域标待设置，禁止派发。
- `.bay` 不能选为区域项目；真实路径校验包含大小写、符号链接和 junction。
- 仅无关联会话/任务的区域允许直接换目录；其余新建目标区域，禁止静默改 cwd。
- 关闭标签、移除登记、归档不删除项目；活动任务先处理再归档。
- 同机移动根目录提供重新定位；使用迁移适配器重建不可变 cwd 对应的本机会话映射，保留逻辑身份。
- 缺少本机历史时要求完整包，不能凭目录声称完整恢复。

## 3. 接口与工作流

UI 与 Agent 共用 Host 服务：工作台创建/打开/重新定位/移除登记；根内目录列举/创建/区域绑定；会话创建/打开/内页查找；任务新建/继续/消息/暂停/恢复/Attention；背景读取/修改/单轮生成；记忆检索/CRUD/修订；完整包预检/作业/进度/取消/恢复。

目录输入为 workbenchId + relativePath。修改携 requestId，更新携 expectedRevision。新任务明确 areaId、内容和模式；继续明确 workItemId；明确续用/隔离策略。返回任务、执行、会话、内页身份，客户端不推断。

### 3.1 多会话与插件

- 删除区域重绑时批量重绑内页；调整合并、移动、浮动固定及插件复用。
- 新对话继承区域 Workspace；打开已有会话要求项目匹配。
- 同一 Session 的多个视图共享会话，背景归属不随活动标签变化。
- Worker 及内页使用任务标题。
- 项目文件浏览器可零 Session 使用，新增 Host 目录适配；不能造空会话。
- 轨迹/审查/会话终端保持具体 Session；插件复用键包含绑定身份。
- 保留工具发现/容器插件集成，定位明确到工作台/区域/项目/Session/资源。

### 3.2 背景生成与注入

| 场景 | 输入 |
| --- | --- |
| 新建工作台 | 用户名称、简介、当前草稿 |
| 工作台背景 | 简介、现有区域及背景、所有区域内页 |
| 区域背景 | 目标区域全部内页；工作台背景只作上层约束 |

入口保持工作台顶栏菜单和区域容器顶栏菜单。辅助填写走独立单轮服务，预填后由用户保存；三场景提示词和模型在交互偏好配置。Main 可调用同一服务并提交允许写入的区段；按钮不进入 Main 历史/循环。

全部目标内页进入收集清单；按类型获取内容/摘要，截断和不可读显式列出。新会话、派发、恢复及模型调用边界读取最新背景；空内容不编造。Main 注入整体背景和区域概览，详情按需；Worker/普通会话注入整体及所属区域。使用投影，不重复追加消息；当前调用保持快照，下一调用取新版。Main 只写 Agent 区，不覆盖人类目标/约束/授权。

### 3.3 Main 与记忆

每工作台唯一 Main，创建空会话不调用模型；重开恢复，既有浮动工作区聊天标签和窗口生命周期不改身份。

记忆记录已验证事实、确认决策、成果位置、阶段进展和区域知识；引用用户确认/任务/事件/文件。任务验收、决策确认、事实核验、交接时更新；Worker 提候选，Main 整理。用户可查改删及追溯。启动/恢复取短索引和进展，调用注入有界摘要，任务细节按需；Worker 只得相关片段。导入对旧环境事实标待核验。背景/记忆/原生历史/编排账本分别保持原始职责。

### 3.4 编排与恢复

保留 NDJSON、checkpoint、Attention、Runtime Adapter。新执行新 Assignment，任务续用 Session；失效/模式不兼容/隔离记录新建原因。同一任务/Session 不并发冲突执行；重复派发幂等，补充指令走消息路径。

有效性含工作台、区域项目版本、Session、Assignment、运行实例；迟到回调不覆盖新执行。事件信封含版本、事件 ID、任务/执行/运行身份、顺序和会话关系；去重、乱序处理保留。Adapter 声明派发/续用/观察/暂停/恢复/迁移能力，缺失迁移能力列完整性阻断。

重启先核查，不确定进入 Attention，不重发。导入保留源状态/checkpoint，展示待继续/待接管；继续使用新运行身份。

## 4. 完整工作台包 V5

类型 `workbench-complete`，工作文件、原生会话和插件制品分别验证，不套用插件文件白名单。

包含全部根内文件/空目录/隐藏/Git/依赖；定义/布局/区域/背景/记忆/可迁移偏好；Main/用户/Worker/关闭标签会话及所需子会话和继承关系；事件/图片/附件/资源；任务/执行历史/Attention/NDJSON/checkpoint；插件声明/可迁移状态/资源映射/可分发依赖；平台/版本/摘要/排除/环境说明。

按持久会话目录和引用关系收集，不按活动标签，也不收集同目录全部宿主会话。默认全文件，可显式排除缓存；必要附件/资源缺失不得宣称完整。Profile 凭据/模型账号/进程不携带；接收方模型或模式缺失统一映射，不静默降级。

### 4.1 原生会话迁移

使用公共日志导出、附件、Session Persistence 能力。保留完整逻辑事件、工具历史、压缩/替换、fork 边界、子会话、标题和模式。导入新本机 Session ID、新 cwd/Workspace；同源多视图映射同一会话。

按类型重映射结构化引用，历史自然语言旧路径不改。恢复附件字节。未知必要事件/缺附件/不可迁移插件明确阻断，不造空会话。导入不重放工具、模型循环、子任务、计划任务、排队输入。

Persistence 无完整公开删除回滚 API：先预检，持久身份映射和进度，失败同作业续导；不依赖删会话回滚。

### 4.2 快照与传输

预检范围/依赖/引用/大小 → 暂停派发并等待受管写入到安全边界 → flush 会话与编排，固定版本/事件边界 → 根外暂存、清单、流式归档 → 恢复原执行策略，原暂停保持暂停。

外部变化检测失败重试或报告阻断，不声称冻结所有外部进程。去整包 Base64：Host 流式压缩/解压，UI 作业信息/路径/分块；进度/取消/持久作业/中断续传；不沿用小包文件上限；有界内存。

### 4.3 导入与平台

选父目录 → 预检版本/摘要/路径/平台冲突/资源 → 持久作业及身份映射 → 文件/附件/依赖/会话/布局/任务/资源恢复 → 核验后登记，等待用户继续。

同作业重试不重建对象；明确再导入创建独立副本并保存来源。半成品不发布；已写原生记录归作业且不激活。

分别呈现数据恢复、运行环境、任务状态。原始内容全保留，用户主动统一恢复环境；首版支持已有 DSH 插件分发及带支持锁文件的 npm/pnpm 项目，其他工具链给诊断和步骤。导入不运行安装脚本。

路径平台无关；根内链接校验后重建，失败明确；根外链接/Git worktree 外部元数据报告外部依赖，不遍历全机；大小写碰撞/非法文件名/缺资源在发布前阻断，不自动改名。保存平台依赖不等于可执行。
