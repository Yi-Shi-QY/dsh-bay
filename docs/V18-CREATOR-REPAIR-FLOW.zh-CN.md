# 18.0 不兼容扩展的创造模式修复入口

更新日期：2026-11-11。修复已纳入 18.0 提交与实验包；当前功能基线 `ab2a7d8`，整版交付范围见 [验证记录](VALIDATION.md)。以下故障分析保留修复前证据。

## 问题与证据

1. 工作台设置使用原生 `dialog.showModal()`；旧修复位置选择器通过 `createPortal(..., document.body)` 挂在该弹窗外。浏览器将原生模态窗口放入顶层，并使窗口外节点不可交互。提高 `z-index` 无法解决。真实 Chrome 中已重现：选择器节点存在，但无法接收指针或焦点。
2. 修复路径传入的 Agent 模式为 `creator`，当前 DSH `0.2.2-rc.2` 官方创造模式在 `presets/cordis.patch.yml` 中注册为 `cordis`。新流程采用实际注册标识，不回退标准模式。
3. 旧工作台关系校验要求所有非 Main 会话都有区域归属，无法保存独立浮动修复会话。当前项目模型允许会话归属持久 Project 而没有展示区域；Worker/子任务也按项目与会话身份保留，派发与呈现时再定位区域。区域内页仍须匹配目标项目。

## 现在的交互

点击“不兼容扩展 → 在创造模式中修复”后，直接执行以下步骤：

1. Host 在当前工作台根目录内准备 `repairs/<模块名>-<身份摘要>/`，并登记原生 Workspace。
2. 为插件的包名和模块标识确定稳定修复身份，预留原生 Session ID。重复请求、失败重试和 Host 重开可使用同一预留身份。
3. 首次创建原生 `cordis` 会话，设置“适配 <模块名>”标题，并登记到工作台会话目录。
4. 使用原生输入接口预填插件身份、版本、诊断和适配要求。保留已有草稿，不自动发送，不调用 Bay Agent。
5. 在现有浮动工作区打开该会话；完成后关闭设置弹窗。准备中禁用重复点击，失败显示错误及重试入口。

再次点击优先显示已有浮动会话；关闭标签后可以重新打开同一会话。若旧视图已固定到区域，可新开同一 Session 的浮动视图，不移动原区域内页。已有聊天不重复插入初始修复说明。

## 目录与迁移

修复目录是独立项目，不创建区域、不改变现有区域的目录绑定。它位于工作台根目录内而不是操作系统临时目录，关闭标签或工作台后保留修复文件和历史。

首次创建的目录不自动包含插件源码。预填说明要求创造模式通过 DSH 原生插件检查能力定位可编辑源码，明确报告缺失项，并将可编辑副本及产物放在修复项目中，避免凭空重建旧插件。

`.bay/workbench.json` 的会话目录保存修复会话的逻辑身份和相对项目路径，不保存固定机器路径。完整包依照已有会话目录收集历史，导入时重建 Workspace 和原生 Session 映射。关闭浮动标签不会删除会话目录记录。

原生创建成功但后续步骤失败时，不假装已经完成。登记失败阻止打开，重试使用预留身份；草稿初始化失败保留已登记会话并释放本次临时引用。重新打开持续会话不覆盖已有输入。

## 验证记录

- 定向回归：真实 Host 目录服务及路由创建修复文件夹，验证布局不变、重复请求、预留身份跨重启复用、登记与草稿失败恢复。
- 会话适配回归：验证传入 `cordis`、重命名、草稿预填、浮动区打开、关闭后复用以及固定视图后的再次打开；会话创建和输入接口使用测试替身。
- 完整包回归：使用原生 JSONL 会话持久化导出并导入独立修复会话，验证历史保留、新原生身份及目标目录恢复。
- 真实 Chrome 回归：`node scripts/validate-creator-repair-browser.mjs`。先重现旧模态与外部 Portal 的交互失效，再挂载实际工作台设置组件，验证直接点击、忙碌状态、可见失败、重试和成功关闭。该检查不调用模型；浮动会话创建由独立集成测试覆盖。
- 完整自动回归：156 个测试文件、1003 项测试通过；最终浮动视图复用调整额外重跑对应测试。
- 类型检查和 DSH RC1 兼容检查通过。测试依赖存在原有的 source map 缺失、jsdom Canvas 等提示，不影响测试结果。

以上数字为修复当时的阶段记录，最新整版结果见 [验证记录](VALIDATION.md)。改动已提交并进入实验包；该阶段未向用户 Profile 安装插件，也未进行真实模型修复任务。自动检查不等同于已完成用户环境实测。

## 安装实验包后的验收

1. 打开一个工作台，不为任何区域绑定项目也可以测试。
2. 在工作台设置中找到不兼容扩展，点击“在创造模式中修复”。应看到准备状态，随后设置关闭、现有浮动工作区打开修复会话。
3. 确认会话使用创造模式、项目位于工作台的 `repairs/` 中，输入框包含正确插件的修复说明；区域数量和原目录绑定不变。
4. 编辑草稿、关闭标签、再次点击修复。应恢复同一个会话，不替换已有草稿、不新增同名会话。
5. 手动发送说明，验证原生创造模式可读取插件资料并开展适配。
6. 需要跨机器继续时使用完整工作台包；接收方仍使用自己的模型配置。
